## Failures

- **S3 (confirmed for comment threads, plausible for Saved Messages sublists and tag filters): the round-2 selection items 3 and 4 are only half fixed.** `src/state/shown_history.rs:9` `Session::shown_history` returns the open forum topic's page, and otherwise `histories[chat]`. The view draws from four sources (`ui/conversation/conversation_part1.rs:560-640`, `rows_cache.rs:196/231/256/277`): Saved (`saved_history()`), then the thread (`thread_for_chat(open)` → `thread.history`), then the topic, then main. Selection mode runs in a thread and in a Saved sublist, because `open_topic_id` returns `TopicId::Thread` or `TopicId::SavedMessages` and `selecting_in` accepts them.
  - Trigger: open a channel post's comments (the thread view moves to the discussion group, `thread_unavailable`), Select a comment from the menu, then click other comments. `message_still_sending` (`selection_drag.rs:438`) finds no message in the discussion group's main history, so it returns `pending = true` and nothing toggles.
  - A drag over thread rows takes its ids from `loaded_selectable_ids`, which also reads the main history. If that history is empty, the release selects nothing. If it is loaded, the release adds main-history messages whose ids fall in the range.
  - Saved Messages sublists behave the same way when the main Saved history does not hold the sublist's rows.
  - Fix: make the shown history follow the view's order. In `Session::shown_history`, check `self.thread_for_chat(chat_id)` first and return `&thread.history.messages`; the Failed-thread case falls through, as the view's does. In the UI, add `QuillApp::shown_history(chat)`: it returns `saved_history()`'s `&history.messages` when the chat is Saved Messages in sublist or tag mode, and `session.shown_history(chat)` otherwise. Use it in `loaded_selectable_ids`, `message_still_sending`, `selected_media`, `selected_messages_text`, the report check and `delete_selected`.
  - Add a state test that seeds `threads.thread` for chat 7 with message 70 and asserts `shown_message(7, 70)` is `Some` while a main-history id is `None`. Add a UI test for a Saved sublist.
  - Also fix the doc lines that claim "what the view draws" (`shown_history.rs:1-3, 7-8`, `selection_mode.rs:298-299`) and the decisions row "Fix round 3 (selection)".

- **S4 regression (confirmed): the new Grams Retry throws away the loaded list after a failed *next* page.** At `src/ui/premium_ui/grams.rs:362-373`, Retry is drawn for any `grams.load.error()` and calls `set_grams_filter(filter)`. `ConnectDriver::set_grams_filter` (`connect/grams.rs:162-172`) sees `load != Ready`, calls `restart(filter)` (rows, offset and receipt cleared) and fetches page one.
  - Trigger: scroll the Grams history until a next page fails, then press Retry. Every loaded row disappears, the list jumps back to the top, and it reloads from the first page.
  - Fix: in the handler, when `grams.rows.is_empty()`, keep `set_grams_filter(filter)`. Otherwise resend the failed page: call `self.grams_more(cx, true)`, or `live.driver.fetch_more_grams()` directly.
  - Extend `a_failed_page_is_drawn_with_a_retry...` so that a Retry with rows keeps them.

- **Flaky test (determinism rule): `src/webauthn/ceremony_tests.rs:331` `a_panicking_worker_ends_with_a_failure_and_a_poke`.** `Link::emit` (`ceremony.rs:341-344`) sends the event *then* pokes `wake::PASSKEY`. `next()` returns as soon as `recv` gets the event, so `assert!(PASSKEY.epoch() > seen)` can run before the worker's poke. The assert then passes only when another test pokes the global signal, and it fails otherwise. The send-then-poke order is correct for production (poking first could wake the reader before the event is there), so keep it.
  - Fix: drop the epoch assert. The poke is `emit`'s job and is already covered. Or have `Ceremony` keep the worker's `JoinHandle` under `#[cfg(test)]` and join it before the assert. Do not spin on the epoch.

## Checked and fine

- **Recording regression.** `with_device_access` checks `recording.busy()` before the OS prompt (`capture_access.rs:188`). `DeviceOs` is the seam, and both new tests drive `with_camera_access`.
- **21-007.** `AttachmentId` is assigned in `push_attachment` and kept through `update_item`, the video/photo editors and the hand-back. `TrayItem` matches by id. The test removes the first entry and shows the twin is not acted on. `TrayItem.path` is still used by the photo editor's decode.
- **Link tooltip.** `note_history_scroll` clears it. `SelectableRichText` ends a hover on a paint that finds the hitbox no longer hovered, and on `MouseExitEvent`. The tooltip is drawn 12/18 px off the pointer, so it cannot cover its own text and flicker.
- **Polls.** `updatePoll` marks the touched entries `Stale` in place. A late `Loading` or `Asking` answer is dropped. A refused ask of a `Stale` entry ends `Failed`. A first-page error now ends `Failed` with a Retry. A purpose-dedup `Ok(None)` leaves the entry `Stale` until the old request settles, and then upkeep asks again, so nothing loops.
- **Stats Retry.** It keeps the dialog and its option, and `fetch_poll_vote_statistics` overwrites `Failed` with `Loading`.
- **Grams.** `GramsView::{Closed, List, Receipt}` replaces `open` and `selected`. `show_receipt` refuses a closed box, `restart` goes back to the list, and `grams_more` asks only on `List`.
- **Premium.** `PremiumAutoStart::is_for` matches the flow's request. `ChatReady.request` is the `ResolvingChat` slot (`session_apply_chats.rs:143`), and the join path carries its own request.
- **Show box.** Reopening while `Saving` keeps the wait for the same kind (tested).
- **`DragSelect`.** `Press::{PickUp, Range { drag: RangePress }}` behaves the same: the range never went back to `None`, and `PickUp` always toggles.
- **Calls privacy.** Each key draws its own Failed row with a Retry. `refuse_privacy_load` runs only when `chats_path_active()` is false (not authorized, or shutting down), so turning a `Ready` key into `Failed` there has no visible cost.
- **Passkey ticker.** It has no timer. A panicking worker and a failed spawn both poke `PASSKEY`. The lock ends the ticker directly, and close or cancel ends it through the worker's final event. `run_guarded` adds no unwrap.
- **Saved topics.** `saved_asked` resets where the list restarts.
- **Proxy editor.** It closes in `SettingsUi::farewell` (tested).
- **Quick replies.** A dedup now returns the in-flight id. `acks.expect` is idempotent, and `delete_quick_reply_message` and `rename_quick_reply` ignore the id.
- **Safety.** No new unwrap, expect, panic, indexing or `RefCell` borrow outside tests. `SendContent::Single` is boxed with no behaviour change.
