## Failures

1. **Sessions and websites changes that never left keep their id in the note.**
   - Where: src/connect/settings/sessions.rs.
     - `confirm_device_login`: begins at :22; the send-failure arm at :27-31 discards the device login and fails `sessions_op`, but leaves the note alone.
     - `terminate_session`: :127 / :130-134.
     - `terminate_all_other_sessions`: :150 / :153-157.
     - `send_session_toggle`: :358 / :361-365.
     - `disconnect_website`: :456 / :462-466.
     - `disconnect_all_websites`: :491 / :494-498.
   - What is wrong: each sender calls `sessions_note.begin(extra)` or `websites_note.begin(extra)` before `send_json`. If the send fails, the request is taken out of the table but `extra` stays in `Waiting { requests }` until the screen is left.
     - No answer will ever come, so `waiting` holds a request that is not out. That breaks the invariant this round wrote into the decisions doc: "`waiting` holds only requests still out".
     - A failed change also takes away any line already shown, because `begin` clears it.
     - The r6 fix asked for exactly this: "In the send-failure paths, settle the id that was begun before reporting the failure". Only block, unblock and masks were done.
   - Fix (pick one and use it in all six):
     - (a) Move each `*_note.begin(extra)` into the `Ok(())` arm, after the send succeeded, the way masks do.
     - (b) In each `Err` arm, call `refused(Some(extra), "<…> request was not sent.")`, the way block and unblock do. This also shows a line.
   - Test: in `src/connect/tests/sweep_r4_05_fix7.rs`, with `recorder.refuse_sends(true)`, call `terminate_session` (with a sessions list seeded so the guard passes) and `disconnect_website` (with a websites list seeded). Assert that the note holds no request:
     - for (a), `== ChangeNote::Idle`
     - for (b), `Refused { waiting }` is empty
   - Add one more such test for `confirm_device_login`, since it uses a different purpose and a different send.

2. **Four of the new `settled` calls have no test that fails without them.**
   - Where:
     - websites_note in session_apply_ok.rs:315-317
     - the toggle arm at :207-209
     - terminate-all-others, which shares the arm at :190-192 but has a different purpose
     - the device link at settings/apply.rs:243
   - What is wrong: removing any of these lines keeps every test green. Only `TerminateSession`, block and mask are covered.
   - Tests to add to `src/state/tests/sweep_r4_05_fix7.rs`, in the same shape as `an_ok_session_answer_leaves_the_note_idle`:
     - `DisconnectWebsite` with `websites_op.begin` and `websites_note.begin`; feed `ok`; assert `websites_note == ChangeNote::Idle`.
     - `ToggleSessionCalls`, ok → `sessions_note` is Idle.
     - `ConfirmDeviceLogin`: set `device_login = Waiting { request }` and begin the note. Feed the success answer through the envelope that `DeviceLoginResult` parses from (the `session` object `confirmQrCodeAuthentication` returns), and assert `sessions_note` is Idle.
