## Failures

1. **scripts/check-owned-timers.py:108-161 (`delay_from_deadline`, `rearm_hits`). The re-arm guard is not narrow: a fixed-period self-re-arm still passes.**
   - **What is wrong:** the rule tests only the timer's own delay. It never tests the argument of the self-call. So the usual re-arm shape passes whatever the period is: `fn arm(due) { timer(due.saturating_duration_since(now)); this.arm(Instant::now() + PERIOD) }`. The probes (scratchpad `probe/probe.py`) found more holes, all of which pass:
     - `let period = Duration::from_secs(10); timer(period.saturating_sub(started.elapsed()))`. A binding used inside a compound expression is never resolved.
     - `timer(self.remaining)`. Any field whose name matches the deadline words passes.
     - `timer(self.due.saturating_duration_since(now).max(Duration::from_secs(10)))`. The text after `.min(`/`.max(` is never tested, so a 10 s floor turns the wait into a 10 s period.
   - **Site that passes only through this hole:** src/ui/inline_playback.rs:415-431, `arm_record_tick`, which re-arms at `now + RECORD_STEP` (a fixed 100 ms).
   - **Fix:**
     1. When the delay comes from a parameter, find each self-call in the body and run the same deadline test on the argument it passes for that parameter. `Instant::now() + X` or `now + X`, where X is a constant or a `let` bound to one, is fixed.
     2. Resolve every identifier in the delay expression through its `let`, not only a bare identifier.
     3. Test the argument of `.max(` as well. A constant floor longer than one frame (more than 16 ms, other than `FRAME`) makes the delay fixed.
     4. Add self-tests in scripts/test_shape_guard.py for the four shapes above, each expected to be flagged.
   - **Owner decision:** once the guard is closed, `poll:QuillApp::arm_record_tick` is flagged. There are two ways forward:
     - An allow line, which needs the owner's OK because the brief bars new ones. The reason: the step is held by `Capture` and lives only while a capture runs, like a frame clock.
     - Or arm the step to the capture's real deadlines: the next chat-action refresh, the round-video limit and the device check. The 100 ms bar redraw then comes from the frame clock while a window draws.

2. **scripts/check-owned-timers.py:183 (`hits`, the loop rule). This loosens the base guard.**
   - **What is wrong:** origin/claude/sweep-r4 flags every `loop`/`while` with `.await` and a timer (`TIMER.search(body)`). The bundle changed this to `fixed_timer(body)`. That function exempts any timer whose argument contains `due`, `remaining`, `saturating_sub` and similar words, with no constant check. So `loop { timer(PERIOD.saturating_sub(spent)).await }` now passes; the probe confirms it. This came in round 2 (347881dcc), and the r2 review missed it.
   - **Fix:**
     - Restore `and TIMER.search(body):` and delete `fixed_timer`. A run of the guard with that line restored still reports "ok (30 baseline hits under 27 keys, 11 allowed)", so no site needs the exemption.
     - Add a self-test with a loop that sleeps `PERIOD.saturating_sub(spent)`, expected to be flagged.

3. **src/notify/custom.rs:42-47 with src/ui/notify_windows/mod.rs:886-900, 917-935 (g-336 / 19-003). Behaviour regression, confirmed.**
   - **What is wrong:** tdesktop's `checkLastInput` reads the idle clock every 300 ms while a notification waits for the user. This round reads it only when something else wakes the clock (a hover, a click, a new notice, the pointer leaving), or at the new 60 s cap.
   - **Trigger:**
     1. On Windows (custom notification windows; `os_idle_ms` is `Some`), a message arrives while the user is typing in another app, after the slide-in ends.
     2. The user goes on typing.
   - **Effect:** before this round, the window hid about 3 s after the next input. Now it stays up for 60 s. Every popup on such a system lingers about 20 times longer, and the queue behind it waits.
   - **Fix (owner decision):** restore the 300 ms idle read, only while a window is `WaitingForInput`, keeping the 60 s cap as its bound. Add the allow line `poll:QuillApp::arm_notify_clock` with the reason: the OS idle clock has no event, and the read runs only while a notification waits for the user. This needs the owner's OK because the brief bars new allow lines. Otherwise the owner accepts the 60 s linger as the product behaviour.
   - **Note:** item 1's hole would also let a 300 ms re-arm through here unflagged, so the allow line must come with the guard fix.
   - **Test:** a waiting window whose idle clock shows input after `started` ends its wait within one check period with no other wake.

4. **src/ui/system_unlock.rs:100-112 (`label`). Regression, confirmed.**
   - **What is wrong:** the `OnceLock<&'static str>` caches the translated text. `tr` reads the live pack snapshot (src/lang/mod.rs:31), and packs are swapped at run time (`install`).
   - **Effect:** after a language change, the "Unlock with Touch ID" / system password switch label stays in the old language. If the first call happens before the pack is installed, it stays in English for the whole run.
   - **Fix:** cache only the `mac::biometrics()` bool in the `OnceLock`, and call `tr(..)` on every call.
   - **Test:** the label follows a pack swap. A unit test over a helper `label_for(biometrics: bool)` is enough.

5. **src/ui/marketplace.rs:30-46 with src/ui/marketplace_box.rs:84-91 (18-001). S4, plausible.**

     - `close_window_boxes`, when the chat window that hosts the box closes;
     - `close_left_dialogs`;
     - `close_blocked_dialogs`.
   - **Trigger:**
     1. Open Marketplace from a chat window and press Buy.
     2. Close that chat window while it sends.
     3. The purchase fails ("not enough Stars").

   - **Test:** in marketplace_box tests:
     1. Open the box, call `asked(7)`, close it.
     2. A purchase with `asked: 7`, stage `Failed`.
     3. `open_for(same chat, resume)` keeps the draft, and `shows` the failed purchase.
