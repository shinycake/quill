With `Waiting` the guard reports `bare:ClearStage::Waiting` (checked on the tip). scripts/check-stage-enums.py says renaming a variant to get past the word list is not a fix. The stage is also split across two fields, `stage` and `messages` (:21-22), which form implicit states. With no messages, `Armed` means "unasked" (`is_unasked`, :104). With asked or made messages, `Armed` waits for an answer or an ack. `Spent` with messages left is draining. `Spent` with none can only be avoided by removing the entry right away (`is_settled`, :130, then the callers' `remove`). Fix: move the list into the variants, for example `enum ClearStage { Unasked, Armed(Vec<SentMessage>), Spent(Vec<SentMessage>) }`. `Armed` then holds the requests it waits for (the guard finds the `RequestId` through `SentMessage` and passes honestly). `ack` and `fail` move `Armed(rest)` to `Spent(rest minus message)` and return whether the entry is finished (`Spent` with an empty list). `is_unasked` becomes `matches!(stage, Unasked)`. Drop the `messages` field.

Fix: add a case where the album and then a text are sent from the same slot (the text's clear replaces the album's). The album's two acks name that slot: first both succeed, then in a second run the first fails. `take_draft_clear` returns `None` for both album messages, `has_draft_clear` stays true for the slot, and the text's own ack then takes the text's clear.
