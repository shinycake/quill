## Failures in the bundle's own work

- **src/ui/toast_queue.rs:168-170 (with 133-139, 147). Regression, S3, confirmed.** Before a session exists, `status_toast_visible` (src/ui/app_render/status_toast.rs:61) calls `drop_toasts()` on every frame. That now stores `Footer::Plain(<toast-kind note>)`, for example the error of a failed sign-in. The old `advance()` blanked a toast-kind note nobody holds on the first live frame. Now nothing does: `Plain` is never blanked, and `clear_note` runs only for startup blockers. After sign-in the stale error stays as `note()`, and the Silent guard at :147 (`self.note().is_toast()`) drops every progress note ("sending", "pinned") until an Info or Error note replaces it.
  - Fix: add a third variant `Footer::Kept(StatusNote)` that `drop_toasts` writes. `note()` returns it only while no session exists, which means `advance` (called only with a session) turns `Kept` into `Footer::default()`. Add a test: `set_note_in(error)`, `drop_toasts()`, `advance()`, then assert `note()` is blank and a Silent note is taken.
- **src/ui/video_player/transport.rs:92-108, src/ui/video_player/mod.rs:183-188, src/ui/video_player/open_wait.rs:11-23. Regression, S3, confirmed by reading.** The bundle removed `spawn_open_poll` (g-434). The replacement wake exists only for FFmpeg (`backend_ffmpeg.rs:266`). The AVPlayer backend keeps the default `on_open` that returns `false`, so `await_open` returns `None`. A macOS clip still `NotOpen` is now redrawn only by vsync frames, and `awaits_picture` stops those after `OPEN_FRAME_WAIT` (10 s). Trigger: a clip that opens after more than 10 s on macOS (slow or external volume, large file). The spinner stays until an unrelated redraw. The comment at transport.rs:93-95 still promises "the open poll redraws the watchers", but that poll is gone.
  - Fix: implement `on_open` for the AVPlayer backend (KVO on `AVPlayerItem.status`, or the status observer that already exists, signalling the oneshot) and return `true`. Then the `NotOpen` branch of `awaits_picture` can go, along with the stale comment.
- **23-011 (src/ui/translate_ui/translate_bar_view.rs:404-406). The skip does not hold.** The entry is plausible, and the skip does not disprove it. It agrees that failed messages are retried only on reopen, and gives effort as the reason ("needs a clock the pump does not have", "tdesktop's source was not at hand"). The tdesktop clone is on this machine.
  - Fix: read tdesktop's translate tracker (`history_translation`/`TranslateTracker`) for its retry rule and copy it. Or give `Translation::Failed { at }` a backoff that the pump retries from the existing poll pass, matched by its request. Either way, add a test for the trigger: fail, reconnect, chat still open.
- **scripts/owned-timers-baseline.txt: `poll:scan 1` is left behind.** g-438 removed the shape (the ble_linux scan now waits on a oneshot), and `check-owned-timers.py --list` has no `poll:scan` hit anywhere. The line is now a stale grant.
  - Fix: delete the line.
- **src/ui/widgets_ui.rs:748-769 (the 24-007 fix). New bug, S4, plausible.** "Request no longer in `session.requests`" is read as "dropped". A normal answer also removes the request, though, and the answer waits in `bots.widget_answers` until `poll_drains` lands it, which is skipped while `lock_waits()` (src/ui/notifications/mod.rs:517). The poll timer (`spawn_screen`, :824) keeps running.
  - Trigger: an answer arrives while locked, then the timer pass turns `Asking` into `Due`. After unlock, `land_widget_answers` fails the `Asking { request: out }` match at :712 and drops the answer.
  - Fix: before calling an `Asking` dropped, skip it when `session.bots.widget_answers` holds an answer for that request (or land answers first). Add a test for "answer pending, not drained".
- **src/ui/story_viewer/story_open.rs:31-34. Doc, S4.** `StoryAsk::NoneOut` says "or a retry clock holds the ask back". `get_story_now` (and the demo path) clears the retry clock before asking, so only a refused send or an already-cached story gives `NoneOut`.
