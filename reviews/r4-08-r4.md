## Failures

1. **src/ui/export_quit_tests.rs:520-550 (`the_exports_ending_closes_the_alert_not_the_box_above`): the new focus assertion probably passes without the kit fix.**
   - What is wrong: the old `close_dialog_by_id` moved focus only when the closed alert's `previous_focused_handle` upgrades to `Some`. That handle is whatever had focus when `exit_after_exports` opened the alert. `new_app` focuses nothing: `new_with_demo`, `QuillShell` and `Root::new` call no `focus`. Compare esc_stack.rs:584-585, whose harness focuses the view by hand for this reason. The main window also has no "focus something when nothing is focused" upkeep. So the alert most likely saved `None`, the old code focused nothing, and `focus_after == focus_before` holds either way.
   - The handover half has no test at all: nothing checks that the box above now restores what was focused before the alert.
   - Fix:
     - Before `ask`, focus a known handle, e.g. `let base = app.read_with(vcx, |app, cx| app.focus_handle(cx)); vcx.update(|window, cx| window.focus(&base, cx));`.
     - Assert that the alert opened over it, i.e. `base` is not focused after `ask`.
     - After the upkeep, keep the current asserts. Add `assert!(focus_after != Some(base.clone()))`, which is what the old code would have produced.
     - Then close the box above (`window.close_dialog(cx)`, then `settle`). Assert that `base` is focused again. This proves the alert's saved handle was handed up.
