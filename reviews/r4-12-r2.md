## Failures in the bundle's own work

- **src/ui/translate_ui/translate_bar_view.rs:479 with src/state/session_translate.rs:357-362. 23-011 still open, S3, confirmed by reading.**
  - What is wrong: `translation_unsettled` is false for `Translation::Pending`. A pump pass that runs while a message's ask is out records the scan without that message (`scan.record`, :483). `PumpScan::candidates` then offers only `wanted` plus `history.messages.changed_since`, and a translation answer does not bump the history revision, so nothing brings it back.
  - Trigger:
    1. Pass N asks for M, so M is `Pending`.
    2. Any later poll pass sees M as `Pending` and drops it from `wanted`. `pump_translation` runs on every poll via poll_drains.rs:52, for example on connection updates while offline.
    3. The ask fails, so M is `Failed{attempts:1}`.
    4. Attempts 2 and 3 are never made.
    5. `translations_back_online` gives attempts back, but no pass tests M.
    6. M stays untranslated while the chat stays open, which is exactly the 23-011 effect.
  - Why the tests pass: pump_tests.rs:341-349 and connection_indicator.rs insert `Failed` over an entry that was never `Pending`.
  - Fix: keep every message that is not `Done` in the scan (`!matches!(.., Some(Translation::Done{..}))`); `needs_translation` already filters `Pending` from the ask. Add a pump test with these steps:
    1. Insert `Pending{request}`.
    2. Run a pass.
    3. Call `finish_translation(request, failed)` until the attempts run out.
    4. Run a pass.
    5. Call `translations_back_online()`.
    6. Run a pass and assert M was asked again.
