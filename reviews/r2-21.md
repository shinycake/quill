# Review of claude/sweep-r2-21: FIX (2 small defects)

Base note: the branch sits on 0bd92845e (main merged in), so `git diff f9fd2d57b...` also shows unrelated main changes (composer_suggest, emoji strip, link handler pin). I reviewed only the two worker commits (d446e32f6, 12c03ae84). check-implicit-state, check-screen-state, check-window-scope and check-file-size pass on the branch.

## Confirmed defects
1. src/telegram/hub/tests.rs, new test `a_replacement_loop_reports_running_without_the_old_hub_touching_it`: it waits with `wait_until(|| bridge.stopped_unexpectedly())`, whose body is a 2 s wall-clock deadline plus `thread::sleep(5 ms)`. AGENTS.md: no sleeps, timeouts or wall-clock waits in tests. Failing scenario: a loaded CI box takes over 2 s to unwind 16 panics, so the first assert fails or the test flakes. Fix: have the source closure hold a drop guard that sends on a channel when the receive loop ends and block on `recv`; or join the loop first. Do not add a new `wait_until` caller.
2. src/system_proxy/mod.rs:174-179 (`refresh`, 06-053): the `WANTED` gate was removed, but `net_watch/mod.rs:315` and `:351` still call `refresh()` on every network change. Once any account ever turned the system-proxy mode on, `READER` exists, so every later network change asks the reader to run the OS proxy detection although no client follows it (before: no-op with nobody following). The new doc comment says "a client that follows it asks", which the callers do not do. Fix: have net_watch only poke the wake, and let `Follow::step` (which already re-reads on connecting) do the asking; or keep a follower count that `refresh` checks.
