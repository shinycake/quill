## Failures

1. **`ChangeNote` waits have no way out on success, or on a send that never left. The note then holds requests that are no longer out.**
   - Where: src/state/fetch.rs:102-147.
   - Every change calls `begin(id)`. Only `refused(Some(id), …)` (:132-147) and `clear` remove an id.
   - Ok answers never touch the note. No handler for `SetSenderBlockList`, terminate, toggle, website disconnect, `ChangeMaskSet` or reorder calls into it.
   - The send-failure paths also leave the id they just began. They call `refused(None, …)`, which keeps `waiting` as it is:
     - connect/settings/mod.rs:214/:222 (unblock)
     - :255/:265 (block)
     - connect/masks.rs:45 (`note_mask_send_failed`; `begin_change` already pushed the id)
   - Effects:
     - After an answered change the note stays `Waiting { requests: [answered] }`.
     - Every later `Refused { waiting }` still lists those answered ids. That contradicts its doc comment, "`waiting` are the changes still out".
     - The list only grows while the screen stays open.
     - For masks the note's ids and `masks.changes` are two copies of the same set. `settle_change` updates one and the ok path leaves the other, which breaks "no two fields kept in step".
   - The r5 single-request note had the same leak. This round turned it into an unbounded list with a stated meaning, and the rubric requires a way out of every stage on the answer.
   - Fix:
     - Add `ChangeNote::settled(&mut self, request: RequestId)`. It removes `request` from the held ids. `Waiting` with none left becomes `Idle`; `Refused` keeps its text.
     - Call it from the ok answer of each change purpose the notes wait for:
       - block and unblock (`SetSenderBlockList`)
       - terminate, terminate-all-others, the two session toggles and the device-link confirm
       - disconnect website and disconnect all
     - For masks, call it inside `MaskSets::settle_change`, so `changes` and the note settle in one place and the error path stops doing it separately.
     - In the send-failure paths, settle the id that was begun before reporting the failure. Either call `settled(extra)` and then `refused(None, …)`, or give `refused` the id: `refused(Some(extra), …)` already removes it and shows the line.
   - Tests, driven through the real envelopes:
     - For block and mask change: `begin` (through the driver send), feed the `ok` answer, assert `note == ChangeNote::Idle`.
     - With two changes out: answer the first `ok`, refuse the second, assert the line shows and `Refused { waiting }` is empty.
     - A send that fails (a failing `RecordingSender`) shows the line and leaves `waiting` empty.
