# Review of r3-12 (Opus, 2026-11-12). Verdict: merge after these fixes

Line numbers are on origin/claude/sweep-r3-12.

- **Sticker video encode leaks its output file when the box closes (regression from the 22-002 change).** `src/ui/sticker_set_box/video_create.rs:34-41`: the worker returns a bare `EncodedSticker { path }`, and the file is wrapped in `OwnedFile` only in the continuation (line 41). The continuation is now `Encoding::Running { _job }`, which the stage owns, so closing the create box, picking another sticker or closing the set box drops it. `encode_sticker` checks the cancel flag only between CRF steps (`src/sticker_video.rs:273`), so a step already running still writes `sticker-*.webm` and returns `Ok`. Nothing wraps that path any more, and the file stays in `quill-sticker-video` until the next startup sweep. Before this change the continuation was detached, so it always ran and its `OwnedFile` removed the file. Fix: wrap the file inside the worker, as the fixer already did for the video editor (`video_editor.rs:494-496`): `encode_sticker(..).map(|encoded| OwnedFile::new(encoded.path))`. Then drop the `.map` at line 41.

- **22-005 is only partly fixed: when the commit's send fails, the box still loses its edits.** `src/connect/sticker_manager.rs:109-113` now returns `Ok(())` after a failed `advance_manager_commit`. The failed step has already been taken off its commit by `next_step` (`state/domains/stickers/manager.rs:134`), and the `Err` arm (`sticker_manager.rs:164-166`) only notes the failure. `finish_manager` sees `Ok`, so `sent` stays true and it clears the box's edits (`src/ui/stickers_manager/mod.rs:254,275`). For a commit with one step (only a reorder, or one removal), which is the finding's own trigger, the user's change is gone and the error toast comes from the drain, exactly as before. Fix: when the new commit is the front of the queue and its first send fails, pop that commit back off the queue, clear the failure that `note_send_failure` set, and return `Err`. `finish_manager` then keeps the edits and shows its own toast. Another option is to put the failed step back at the front of its commit (`steps.push_front`) so the next pump sends it again. Add a test where the sender refuses the first send and the box keeps its removals.

- **23-002 is only partly fixed: `State::timer` keeps the same hand-cleared flag shape.** In `src/ui/userpic_videos.rs:690`, the timer's task clears `state.timer = None` through `videos.with(..)`, which skips the write when the borrow fails. `arm_timer` arms only when `state.timer.is_none()` (line 674). One failed clear therefore leaves `Some(finished task)`, and no release sweep is ever armed again: players are no longer paused or put to sleep. That is the failure the finding describes for `sweep_due`, and the finding lists `State::timer` in its fields. Fix: make the armed stage self-ending. Store the due time with the task (`timer: Option<(Instant, Task<()>)>`, or `enum Sweep { Idle, Armed { due, _timer } }`), and let `arm_timer` re-arm when it finds no timer or one whose `due` has passed. The timer then no longer depends on a second borrow to leave its stage.

- **The single `SetEditing` value makes the set box's controls lose their effect, without telling the user, while a pick is `Waiting`.** While a chosen sticker downloads or decodes (`SetEditing::Waiting`), the set box still draws "Edit Stickers" (`src/ui/sticker_set_box/mod.rs:494`) and the add cell (`mod.rs:438`, gated only on `!reordering`). Pressing "Edit Stickers" does nothing, because `begin_reordering` accepts only `Idle` (`state.rs:161`). Opening the chooser from the add cell runs `enter(Picking)` (`creator.rs:356-360`), which silently drops the waiting pick: if the user then cancels the chooser, the sticker they picked first never reaches the editor. Before this change `pick` and `pending` were independent, so the first pick survived. Fix: draw "Edit Stickers" and the add cell disabled while `editing` is not `Idle`, for example with a `SetEditing::is_idle()` read in the footer and grid. Then no state the user cannot see blocks a press, and opening the chooser cannot end a wait.
