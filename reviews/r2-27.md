Verdict: FIX

## Defects (confirmed)

1. `src/ui/gifs_ui.rs` `request_gifs` / `follow_gif_wanted` / `gif_tab_upkeep` (10-002, 10-003): `request_gifs` writes `self.pickers.gif_tab = GifTab::Asked(..)` unconditionally, which drops a `GifTab::Typing` pause timer. The old keystroke counter never lost a pending search to an ask.
   - Failing scenario: two windows have the GIF tab open. Window A searched "cat", then window B took the session's list. In A the user types "cats". `gif_tab` becomes `Typing { wanted: Search("cat") }`. On the next frame `pressed_here()` runs `follow_gif_wanted`. A is `Found`, nothing is on its way, so it calls `request_gifs(Search("cat"))`. The stage becomes `Asked`, and the timer for "cats" is dropped. "cats" is never searched until another keystroke.
   - The non-pressed path does the same, because the `Asked` guard is false in `Typing`.
   - Fix: in `request_gifs` keep an existing `Typing` stage when the ask is for the same `wanted` it carries, or have `follow_gif_wanted` and `gif_tab_upkeep` skip while `Typing`. Add a test: `Typing`, then `gif_tab_upkeep` with a `Found` section, and the timer is still held.

2. 09-122 (skip is unsound): `frame_clock.rs` `AppGate::{active, held}` and `FrameUi::{window_active, main_covered}` are the same fact held twice, written together in `follow_windows` by hand. The decision doc admits it ("written in the same call"). A test that asserts the copies agree after each transition proves the coupling instead of removing it. This is what the entry names. Fix: have `FrameUi` read the `AppGate` global, or the reverse, so there is one value.
