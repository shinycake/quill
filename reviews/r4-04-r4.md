## Non-blocking notes

- **`src/connect/tests/paid_messages_guard.rs:226-231`: the new driver test reads the wall clock.**
  - It takes `unix_ms_now()` after `remember_paid_trust` read its own, and assumes the two readings are less than 30 s apart with no backward clock step. Lines 129 and 139 of the same file already do this, so this is not new practice.
  - Deterministic alternative: drive the read with `f.1.paid_trust_tick(1_000)` and assert `!trust_read_due(1_000 + TRUST_RETRY_MS - 1)` and `trust_read_due(1_000 + TRUST_RETRY_MS)`. Then call `remember_paid_trust` and assert the directory is untouched and no save error is set.
- **`src/proxy_ops.rs:206-211` (`fetch_unsent`): an unsent retry resets the failure count.**
  - `NotSent { at }` carries no `tries`, so a `Failed { tries: 5 }` whose retry cannot be sent restarts at 30 s.
  - Unsent only happens when the client is closing or on a native send error, so this is harmless. Carrying `tries` through `NotSent` / `NotSentStale` would make the count exact.
- **`src/ui/new_chat/mod.rs:322-342` (`set_new_chat_stage`) still matches `left` by hand instead of calling `left.released_by(&stage)`.**
  - Its behaviour is correct today: every caller sets a different stage.
  - Using the pure fn there too would leave one decision site.
- **`src/ui/new_chat/mod.rs:44`: the `unkeyed:TitleCheck::Sent` baseline hit sits in a file round 4 edited.**
