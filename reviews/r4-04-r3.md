## Failures

- **`src/ui/new_chat/mod.rs:303-340` (`settle_new_chat_stage`, r2 S4 "settled type Save leaves its rows"): no test covers the fix.**
  - The release decision (`Release::Create` / `Release::Save`) sits inside a `QuillApp` method. Deleting the `Save` arm fails no test (`grep forget_new_chat_type_save` finds only the two callers and the driver fn).
  - Fix: move the decision into a pure fn in `src/new_chat.rs`, e.g. `NewChatStage::released_by(&self, now: &NewChatStage) -> Option<Release>`. Test it there: Saving(sent) to Type{Idle}/Failed/Closed gives `Save(sent)`; Saving(sent) to the same Saving gives `None`; Creating has the same cases. The UI then only calls the driver.

- **`src/state/domains/payments/apply.rs:158-164` and `error.rs:70-77` (r2 S3 "resale purchase outlives its box"): the notice push is untested, and the demo session does not reopen.**
  - `marketplace::stage_tests::an_answer_with_the_box_closed_comes_back_for_a_notice` covers `GiftPurchase` only. If the `&& let Some(answer) = ...` arms in apply.rs or error.rs stopped pushing `boxless_notice`, no test would fail, and that push is the user-visible fix.
  - Fix: add a Session-level test in `src/state/tests/` that applies a `sendResoldGift` answer and an error to a `SendingClosed` purchase and asserts `payments.notices` gets one Info and one Error entry. Also assert that an open box (`Sending`) pushes none.
  - `src/ui/marketplace.rs:57-64`: `close_marketplace_box` closes the demo session's purchase, but the reopen path only touches `self.live`. A demo purchase closed and reopened stays `SendingClosed`, so its answer raises a notice while the box shows it. Fix: mirror the `else if let Some(session) = self.demo_session` branch in the reopen block.

- **`src/location_picker/picker.rs:517-522` (`search_places_in_area`) with `move_ended` at 391-395: "search this area" ignores a settled query, and the next pan then sends that query by itself.**
  - This is r2 Trigger B's second half, which round 3 left open. With "pizza" settled, press "Search this area": it asks `""` while the field shows "pizza". The next pan finds `unasked_query() == Some("pizza")` (the ask's query is `""`), so `move_ended` sends "pizza" at the new center with no button press. That is a search started by a pan, which tdesktop never does.
  - Fix: `search_places_in_area` asks the settled query, i.e. `self.venues.input.query().filter(|_| self.venues.input.is_shown()).unwrap_or("")`. Then `unasked_query` stays "a query typed with no place yet". Add a test: Settled "pizza" answered at A, pan, "search this area" asks "pizza" at the center, and a further pan sends nothing.
  - `picker_tests.rs:521-534` (`a_query_typed_then_a_pan_then_the_fix_is_still_sent`): the final assertion `at.same_place(&here) || at.same_place(&point(10., 10.))` passes for either point. The code keeps the pan's ask at (10,10). Assert that exact point, so a later change to where the query goes shows up.

- **`src/ui/gift_manage_ui.rs:279-281` (`gift_collection_tabs`, r2 S3 "failed collections fetch"): the Retry is hidden in the case the item was about.**
  - Opening someone else's gifts makes the first `getGiftCollections` fail with nothing held, so `collections().is_empty() && !mine` returns an empty div before the Retry button at 301-313 is reached. Their collection tabs stay missing with no error and no retry, the same effect r2 reported.
  - Fix: `if manage.collections().is_empty() && !mine && !manage.collections_fetch.is_failed()`.

- **`src/proxy_ops.rs:10-12, 69-71` (`ProxyFetch::Failed { at }` / `FailedStale { at }`): a failing `getProxies` is asked again every 30 s for the whole session.**
  - `FAILED_RETRY_AFTER` is a fixed period with no growth and no cap on tries, and it applies to background accounts too.
  - Fix: carry `tries: u8` in `Failed`/`FailedStale` (as `TrustFile::SaveFailed` does) and double the wait per failure up to a cap, e.g. 15 min. Extend `a_failed_fetch_keeps_what_it_owed_and_is_retried` with a second failure.

- **`src/paid_messages_trust.rs:125-132` (`trust_load_failed`) and `src/connect/paid_messages.rs:62-76` (r2 S4 "read errors become no file"):**
  - `LoadFailed { retry_at_ms }` retries every `TRUST_RETRY_MS` (30 s) forever with no growth. Fix: `LoadFailed { retry_at_ms, tries }` with `trust_retry_after(tries)`, as the write side does.
  - The real fix is the `ErrorKind::NotFound` split in `load_paid_trust`, and nothing tests it. `an_unreadable_trust_file_is_not_overwritten` calls `trust_load_failed` directly, so reverting the driver to `.ok()` still passes. Fix: add a driver test that puts a directory at `paths.root.join(TRUST_FILE)` (`read_to_string` then fails with a non-NotFound error). Assert that `remember_paid_trust` writes nothing over it and `trust_read_due` is false until the wait ends.

- **`scripts/stage-enums-allow.txt:38` (vs `origin/claude/sweep-r4`): an allow line was reworded.**
  - `bare:WithdrawalState::Pending` keeps its key, but its reason now names `src/earn/revenue.rs` instead of `src/premium_hub/ton.rs`, and the line moved to the end of the file.
  - This came in round 1 (c9776bc0c), when `ton.rs`'s variant was renamed to `Unsettled`. The new name is accurate: it mirrors Fragment's state, and nothing Quill started is behind it. The reworded text is also accurate, because the remaining bare `Pending` is `earn/revenue.rs:99`. Still, the rule is that no allow line changes, and earlier reviews missed this one.
  - Fix: restore the base line byte for byte (the key still matches), or get the owner's OK for the corrected path. Nothing else in the allow and baseline files was added or reworded. Every other change is a removal.
