## Failures

1. **Four existing tests now fail: a refusal with no `begin` lands nowhere.**
   - `ChangeNote::refused` (fetch.rs:117-125) drops `(Idle, Some(_))`. These tests send the request and call `*_op.begin`, but never `*_note.begin`, then assert the line:
     - src/state/tests/sessions.rs:266 `terminate_session_error_surfaces_honestly` (asserts `Some("Could not terminate…")`)
     - :588 `disconnect_all_websites_error_surfaces_honestly`
     - :683 `toggle_session_secret_chats_error_surfaces_honestly`
     - :751 `a_failed_terminate_keeps_the_list_and_shows_the_error`
   - The round edited sweep_r4_05_fix2.rs and masks.rs to add `begin`, but missed these four. The gate will go red.
   - Fix: these tests go through the state layer, so call `session.settings.{sessions,websites}_note.begin(extra)` right after the request in each, the way sweep_r4_05_fix2.rs does. Better: drive them through the `ConnectDriver` send (`terminate_session`, `disconnect_all_websites`, `toggle_session_*`) so the test covers the `begin` the driver does. Keep the existing assertions.

2. **A block sent from the chat bar sets the Privacy page's note, so a stale line comes back when Privacy opens.** This is the r4 bug again, through another entry point.
   - The chat bar block confirmation (chat_bars.rs:457) calls `driver.block_sender`. The driver (connect/settings/mod.rs:247) now calls `block_note.begin(extra)` with no Privacy page open.
   - Trigger: offline, block from the chat bar, and TDLib refuses when the connection returns. The note goes `Waiting` → `Refused`, and nothing clears it, because Privacy was never open to be left.
   - Opening Privacy later shows "Could not change the block list". The same block from the bar also replaces a wait the Privacy page holds, so the Privacy refusal is lost.
   - Fix, pick one:
     - The note's wait starts only from the Privacy page's own block or unblock. Take `begin` out of the driver: return the id and have `PrivacyUi::block_user` / `unblock_user` call `block_note.begin(id)`, or pass an origin to the driver.
     - Or also clear the note where Privacy opens (`arrive_settings_page(Page::Privacy)` → `leave_blocked_list()`).
   - Test: `block_sender` through the driver with Privacy not open, feed the error envelope, then `arrive_settings_page(Page::Privacy)`, then assert `block_note.line().is_none()`.

3. **With two changes out at once, the first one's refusal is shown nowhere while its screen is still open.**
   - `begin` replaces the single held request. Masks can have several changes out: `changes: Vec<MaskChange>`, and connect/masks.rs:137 (`set_change_pending`, masks.rs:163) blocks only a second change of the *same* set, or any change during a reorder. So install A, then archive B, then A is refused: `settle_change` drops A, and `change_note.refused(Some(A))` is ignored because the note waits for B. No line appears, and nothing undoes anything, so the manager shows A as installed until the next refetch.
   - Blocks are the same: the Privacy list allows unblock X, then unblock Y while X is out (no busy gate in privacy/mod.rs:547). X's refusal puts X back in the list without a word.
   - Before this round both refusals were shown. That is a silent failure while the owner is on screen, against "every stage has a way out: the answer, the error".
   - The sessions and websites notes are not affected: their `*_op` gate (`is_mutating`) allows one change at a time.
   - Fix: let the note wait for every request it was given. For example, `Waiting { requests: Vec<RequestId> }`. `begin` pushes, an answer or refusal removes its id, and a refusal of a held id moves to `Refused { text, waiting: rest }` (or keep the waits in a field beside the shown line). `clear` drops everything. For masks, you can instead key the refusal to `settle_change(pending.id)` returning `true` while `dialog_open()`.
   - Test, one each for masks (two different sets) and blocks (two users):
     - send two changes
     - refuse the first through the error envelope
     - assert the line is shown
     - then refuse the second after the screen is left, and assert nothing is shown on reopen
