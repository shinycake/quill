## Must fix (S3, confirmed)

- **src/state/session_date_jump.rs:34-41 (`DateAsks::forget_chat`).** Asks are keyed by the asking window (`asked_in.chat()`, `None` = main). The callers pass the chat the *main* window left: `session_chatlist.rs:207` and `session_window_chats.rs:195`. So `forget_chat(Some(c))` removes the ask of `c`'s chat window, and the main window's own ask (key `None`) is never forgotten when it leaves `c`.
  - Trigger: Bob is open in his own window and in the main window. Pick an off-calendar date in Bob's window; while `getChatMessageByDate` is out, select Alice in the main window. The answer settles nothing, and the jump silently does nothing.
  - Reverse trigger: the main window asks in A, leaves A, and returns; the late answer still jumps.
  - The fix-table line "a newer pick of the window replaces its ask" holds, but the leave path is wrong.
  - Fix: store the chat with the ask, `HashMap<Option<ChatId>, (ChatId, RequestId)>`. `forget_chat(Some(c))` removes the main-window entry (key `None`) whose chat is `c`. A chat window's key goes when that window closes (`close_window_chat`). `None` still clears all.
- **src/state/sticker_gif_types.rs:592 (`GifPanel::saved_failed`), called from src/state/domains/stickers/error.rs:247.** A `getSavedAnimations` error is matched by purpose only.
  - Trigger: R1 is out. `saved_forgotten` (show_saved_gifs, or an Add/Remove ok) moves the stage to Idle, then R2 goes out as `Loading{R2}`. R1's error writes `Failed`, so R2's answer fails `waits_for` and is dropped.
  - Effect: an error and a stale list until the panel reopens.
  - Fix: `saved_failed(request: RequestId)` acts only when `self.saved.waits_for(request)` (keep the outdated guard), and error.rs passes `pending.id`. The send-refused path in connect/stickers.rs keeps the request it just took. This is the same shape as g-067/g-063, so per the "fix it everywhere in your files" rule it belongs to this bundle.
- **src/state/session_privacy_data.rs:375-378 (`ResetNetworkStatistics` error arm).** `data.network.fail(..)` is unmatched and lands on the refetch's `Loading{R}`; connect/privacy_data.rs:270-271 resets `network` and sends the refetch right after the reset.
  - Trigger: press Reset in Network usage, and `resetNetworkStatistics` errors.
  - Effect: `network` becomes `Failed{stale:None}`, the refetch answer is dropped, and the panel shows the error with no numbers until it is reopened. This is 09-002 moved from the ok path to the error path.
  - Fix: keep the reset's outcome out of the fetch. Add a `NetworkReset::{Idle, Sending(RequestId), Failed(String)}` on `PrivacyData` matched by `pending.id`, and leave `network` to its own request. Add a test next to `a_reset_leaves_only_the_fetch_asked_after_it` for the error order.
