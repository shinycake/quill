Add a UI-level test that a Buy press during `Verifying` leaves the checkout alone.

## Reviewer's notes (after the pre-review above)
Verdict: FIXED by the reviewer, merged into claude/sweep-r2-followup.
- Defect 1 (02-092): confirmed that the UI closed the checkout before asking, so the driver's refusal while `Verifying` could not fire. The scenario in the pre-review is not quite the one that breaks: the old `sendPaymentForm` has already answered by the time the stage is `Verifying` (that answer is what sets it). What breaks is the next poll, which opens the verification page and closes "the checkout of that payment" (`closes_checkout`): a form started in between is the one that gets closed. Fix on the branch: `start_invoice_checkout` writes nothing before it asks; `send_payment_form_request` replaces the checkout and its note only once the request went out, and a refused form leaves the checkout whole. The connect test covers the refusal (stage, invoice and note untouched) and the replacement after the verification ends. A UI-level test is not possible without a live driver, which is why the state writes moved into the driver.
- At the merge: r2-01 rebuilt the same checkout value (10-117, 10-118: `checkout_form.rs`, the note inside the checkout, a `Failed` stage). The integration branch keeps r2-01's structure with this branch's rule (refused while `Verifying`, replaced only after the send).
- Nits left: 02-083 re-offers `ensure_media_files` only while the sender itself refuses, which costs nothing; the chatbots Retry that ignores its `Result`.
