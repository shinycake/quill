# Review of r3-04 (Opus, 2026-11-12). Verdict: merge after these fixes

Line numbers are on origin/claude/sweep-r3-04.

- **Regression: the group sticker-pack picker now hangs on "Loading packs" for good (08-017).** `load_group_sticker_choices` sends `getInstalledStickerSets` and only calls `fetch.begin()` (src/connect/groups/mod.rs:61 and :71), never `fetch.sent(extra)`, so `lists.installed` sits at `Loading { request: None }`. The new gate at src/state/domains/stickers/apply.rs:16-28 asks `installed.answered(Some(pending.id), ())`, which returns false, so `current` is false. The answer is then dropped: `accept_installed_sticker_sets` is skipped at apply.rs:58, and `accept_installed_sticker_sets` no longer calls `succeed` either. The list stays Loading, so the button in src/ui/group_edit_box/extras.rs:197-207 stays disabled with "Loading packs" and the sets never show. The `is_loading()` guard at groups/mod.rs:58 also blocks any re-ask. Before this branch, `accept_installed_sticker_sets` stored the sets and marked the list Ready whatever the request. Fix: call `fetch.sent(extra)` right after `fetch.begin()` at groups/mod.rs:71 (the emoji half too). Better: route the sticker half through `sticker_request`, as media_library.rs and message_menu.rs now do. Add a test that answers `load_group_sticker_choices` and checks that `stickers.sets` is filled and `lists.installed` is Ready.

- **09-011 is only half fixed: ads stay hidden after they are turned back on, and after Premium ends.** `sponsored_hidden` is still a session-long bool, set from three places (src/state/session_sponsored.rs:346, :460, and the toggle ok). Only one path clears it: a `getUserFullInfo` *response* for the own user (src/state/session_apply_users.rs:35-37). TDLib reports a change to the setting with `updateUserFullInfo`, and that arm (src/state/domains/users/apply.rs:216-250) never clears the bool. So turning ads back on in another client, or with Quill's own Business "Do Not Hide Ads" switch (src/connect/business_extra.rs:302, whose saved value arrives as `updateUserFullInfo`), leaves ads hidden and unfetched until restart. Premium ending is not handled either: `has_sponsored_messages_enabled` stays false for a non-Premium account, so the latch never clears, although the decision-doc row claims a Premium lapse is covered. Fix as the register says: delete the field and derive `sponsored_hidden()` = `my_is_premium() && own full info's extras.sponsored_enabled == false` (when no own full info is cached, use the server's answer, or ask `getUserFullInfo` for self). Make the `toggleHasSponsoredMessagesEnabled(false)` ok and `ReportSponsoredResult::AdsHidden` write `extras.sponsored_enabled = false` into the own cached full info instead of a separate bool. Fix the decision-doc row. Add a test that drives `updateUserFullInfo` (enabled) and a Premium-to-non-Premium `updateUser`.

- **The bundle's own counter guard flags a counter in a bundle file, and the fixer added it to the baseline instead of fixing it (file-complete rule).** `LanguagePurpose::PsaLabels { epoch: u32 }` (src/state/domains/settings/language.rs:32) is exactly the "counter in a purpose standing in for the RequestId" shape that the new `counter` rule rejects. The fixer added it to the baseline as `counter:LanguagePurpose 1` (scripts/request-match-baseline.txt:6). `PsaLabels::store` (src/promotion.rs:248-275) writes the badge texts when the epoch matches, whatever the request. Fix: drop `epoch` from the purpose. In `store`, write the strings only when some `PsaAsk::Asking { request }` waits for that `request`; `plan()` already clears `asks` when the pack changes, so an older pack's answer finds no waiter. Then delete the `counter:LanguagePurpose` baseline line.

- **The new `counter` rule misses the shape this bundle removed.** `COUNTER` (scripts/check-request-match.py:62) matches only a bare `uN`, so a field like the old `SetOption { generation: Option<u32> }` passes unflagged. Fix: `r"\b(?:generation|epoch|token)\s*:\s*(?:Option\s*<\s*)?u(?:8|16|32|64)\b"`. Re-run the check, and add any new hits to the baseline only if they sit outside this bundle's files.
