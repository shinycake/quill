- src/calls/engine/tgcalls/sound.rs:20-27, 128-139 (IS, a stage with no way out on error). When the device open fails, the open closure logs the failure and returns `Err`, but the stage stays `Opening { thread, token }`. Nothing outside tests reads `opened()`, so the slot keeps saying "opening" and holds a finished thread until the next `clear()` or `open()`. The final re-read will record this as a stage that the error does not leave. Trigger: start a call with no usable output device. Fix: in the `Err` arm, call a `slot.open_failed(&landing)`. Under the lock, it sets `Stage::Closed` only when the stage is `Opening` with that token (compare with `Arc::ptr_eq`, the same way as `publish`). Then update the `Closed` doc to "no output: before the first open, after `clear`, or after the open failed". Add a test: an open that fails leaves the stage `Closed`, and a reopen still lands.

- src/agent/server.rs:395-407 with src/agent/events.rs:316-322 (S4, lost wake-up, part of 01-002). The watcher checks `flag.is_current(mine)` without holding the `MESSAGES` lock, and only after that does `park` take the lock and wait. Trigger: an unsubscribe or a dropped connection lands between that check and the wait. `stop()` sets `Stage::None` and notifies while no thread is waiting, and the watcher thread then stays parked for the full `WATCH_PARK` (600 s) after its connection is gone. The new test works around the race by calling `wake_waiters()` in a loop. Fix: `park(timeout, still_wanted: impl Fn() -> bool)` takes `MESSAGES`, returns at once if `!still_wanted()`, and only then calls `wait_timeout`. The watcher passes `|| flag.is_current(mine) && conn.ended().is_none()`. `stop()` already sets the stage before it takes `MESSAGES` to notify, so the lock order is safe. In the test, call `stop()` once with no loop.

The four judgment calls:
- `EditImageFetch::Tracked { file_id }` is not a guard dodge. Quill's request (when there is one) is owned and matched by the download tracker. With `Ok(None)` there is no request of ours at all, so no `RequestId` could go in the variant. The stage holds the tracker's key, and its two exits (landed, `gave_up`) are read from the tracker each frame. The old allow line gave the same reasoning, so the name is accurate. The new test covers the `asked` decision and `gave_up`, but not the full UI flow the first review asked for. That is acceptable.
- Keeping a confirmed birthdays hide revivable by a fresh list is right. The server decides how long a hide lasts, and a fresh close-birthdays list after the hide was taken is TDLib saying the card applies again. The pre-existing connect test also expected the card back after a fresh list. The race the review raised (a list arriving while `Hiding`) is fixed and tested.
- `DeviceRun` with an `Arc<DeviceThread>` is acceptable. The `Arc` is never cloned outside `start`. In `start`, the count is 2 for one statement and back to 1 once the old variant drops, so dropping the stage still closes the device. A by-value `start` would need a placeholder at every `&mut` call site, and that is what the review objected to.
- The rest of the bundle's renames are accurate names for engine or derived states, as found in the first review.

Guards: request-match, stage-enums, owned-timers and refcell-borrows `--list` show no hit in any bundle file, and `check-implicit-state` passes. Compared with the base, the baseline and allow files only lost lines. No line was added or reworded.
