This is the re-review after fix round 2, at tip 013e02682 (`origin/claude/sweep-r4-04`). Every item from r4-04.md is fixed (see "Checked and fine"). The full re-read of all 32 bundle files found the items below. Five of them are confirmed or plausible S3s that the final sweep would record.

## Failures

### S3

- **`src/location_picker/picker.rs:131-137, 380-401, 511-515`: the venue list spins forever with nothing asked.**
  - Trigger: open the picker with no earlier fix (`ListData::Unlocated`). Pan the map while it is still locating. `move_ended` sets `search_location = Some(center)` and sends nothing. Then the fix is Denied or Unavailable. `wait_for_location` writes `WaitingForLocation` only when `search_location.is_none()`, so the list stays `Unlocated`, and `venues()` shows it as `VenueView::Loading`. The only way out is "search this area".
  - Root cause: `ListData::{Unlocated, WaitingForLocation}` repeats `search_location.is_none()` and `request.is_none()` by hand (an IS in the same place).
  - Fix: `ListData` keeps only answered data (`NothingFound`, `Found`). The view derives the rest: no ask while `here == Locating` is Loading, and no ask otherwise is WaitingForLocation.
- **`src/location_picker/picker.rs:495-509` (`request_venues_for_fix`) with `move_ended` at 380-401: a query typed before any place is known is never sent once the map was panned.**
  - The fix-round claim holds only on the path with no pan, followed by `Found`.
  - Trigger A: type "pizza" with no location, so the input goes to `Settled`. Pan, then the fix arrives. `search_location` is already `Some`, so `typed` is `None`. The query is non-empty, so the last arm sends nothing, and the list spins under "pizza".
  - Trigger B: Denied, type "pizza", then pan. Nothing is sent. "Search this area" then asks with query "" while the field shows "pizza".
  - Fix: decide on "no ask was made for the settled query" (`venues.request` is `None`, or its query differs) instead of `search_location.is_none()`. Run the same send from `move_ended` when a `Settled` query has no ask.
  - Add picker tests for pan-then-Found and Denied-then-type-then-pan.
- **`src/peer_qr/theme.rs:518-531` (`ThemeGifts::fail`): a failed first page counts as a complete empty list.**
  - The `First | FirstAsking(_) | FirstFailed => Listed(GiftsRest::Complete)` arm runs on a reconnect drop (`PeerQrData::forget_dropped`), a TDLib error (`users/error.rs:70`) and a send failure (`connect/peer_qr.rs:99`).
  - Effect: a user with gifts sees "no gifts", and `wants_more` is false, so nothing retries until the box is reopened. `refuse` already uses `FirstFailed` with Retry.
  - Fix: map those three to `GiftsStage::FirstFailed`, and add a test.
- **`src/marketplace.rs:127` (`GiftPurchase`) with `src/ui/marketplace.rs:51-55, 103-106`: a resale purchase outlives its box.**
  - Trigger: confirm "Buy", then close the Marketplace box before `sendResoldGift` answers. `on_close` closes only the UI draft. `accept_result` (`state/domains/payments/apply.rs:156-163`) raises no notice, and the next open clears the purchase.
  - Effect: the success line (Stars spent) or the refusal / price-changed line is never shown.
  - Fix: a `Sending { shown: bool }` or `SendingClosed` stage, as `SendStep::SendingClosed` in gift_manage does. The close moves to it, and an answer that lands with no box pushes a `PaymentNotice`.
- **`src/gift_manage/state.rs:364-372` (`CollectionsFetch::settle`) with the error arm at `src/state/domains/payments/gift_manage.rs:359-362`: a failed collections fetch is treated as loaded.**
  - The error settles to `Idle`, the same value as a loaded list, and `refresh_gift_collections_if_stale` asks only from `Stale`.
  - Effect: the collection tabs are missing with no error and no retry until the list is reopened.
  - Fix: add `CollectionsFetch::Failed(reason)` (or `Stale` when it was `LoadingStale`), shown with a Retry.
- **`src/passcode/idle.rs:291-296, 308-337` (`sampler::start`): a sampler thread that dies is never restarted. Plausible.**
  - Trigger: the `quill-idle` thread panics (zbus, x11rb or a backend parse). `spawn_guarded` catches it before the thread reaches `*sampler = Sampler::Stopped`, so the stage stays `Running`. Every later `start()` only bumps `last_read_ms`. `IdleCache::Sample` then extrapolates without bound.
  - Effect: auto-lock sees the user as idle while they type, until restart.
  - Fix: treat `Running { _thread, .. }` with `_thread.is_finished()` as `Stopped` (the `icon_badge::launcher_worker_runs` pattern), or add a drop guard in the thread body that sets `Stopped` and resets `IDLE` to `Unknown` on any exit, panic included.
- **`src/proxy.rs:741, 748` (`ProxyState::list` beside `ops: ProxyListOps`; `ProxyFetch::Failed` at `src/proxy_ops.rs:30`): a failed refetch loses the stale mark. Plausible.**
  - Trigger A: a change succeeds and sets `Stale`, and the refetch errors. `Failed` drops the stale mark, and `system_proxy_tick`, `rotation_step` and `all_entries` then plan on the old list until the user opens the proxy box.
  - Trigger B: the first `getProxies` errors, so `list` stays `None`, and system-proxy and auto-switch never run.
  - Fix: `ProxyFetch::Failed { at, stale }` (or `FailedStale`). A stale failure counts as busy, and `refetch_due` retries a failure after a backoff, as `NotSent`/`NotSentStale` already do.
- **`src/net_watch/mod.rs:351-378` (`Watcher::ensure_with`, `tracker()`): a replaced listener does not read the route again. Plausible.**
  - Trigger: the listener ends on the event of a Wi-Fi A to Wi-Fi B switch (Linux socket error, a panic in `heard`, or the macOS run loop ending). The restart does not call `network_changed()`, so `route` and `epoch` stay old. `look_due` only re-looks while offline.
  - Effect: TDLib keeps dead connections ("Connecting…") until some later event.
  - Fix: have the new thread run `network_changed()` once after it subscribes. Do not call it under the WATCHER lock, because `network_changed` takes TRACKER and calls `tracker()`.

### S4

- **`src/net_watch/mod.rs:351-358`: a listener that can never start is respawned every `WATCH_RESTART_AFTER` (5 s) for the whole session**, including while locked or hidden. Trigger: netlink `subscribe()` is refused in a sandbox, or `SCDynamicStoreCreate` returns null. Fix: a failure count with a doubling, capped `retry_at` in `Running`, or `Watcher::Unavailable` after N quick ends.
- **`src/proxy.rs:983-989` (`rotation_step`, the "every alternative failed" branch): the rotation wipes the proxy box's `pings`.** That includes a user's in-flight `Checking(req)`, whose answer is then dropped by `take_awaited_ping`. Fix: keep the rotation's verdicts in the rotation stage (`tried: HashSet<i32>`), or at least remove only `Unavailable` entries and leave `Checking(_)`.
- **`src/peer_qr/theme.rs:369, 472-479` with `src/ui/peer_qr/gifts_panel.rs:95, 184`: the `GiftsRest::Waiting { retry_at_secs }` deadline is only compared from render.**
  - Nothing fires at the deadline, so with no repaint there is no retry. With constant repaints and a failing server, the page is asked every 5 s with no cap.
  - Fix: back off and cap the tries (as `PaidStage::Stuck` does), or hold a `Task` on the UI side that notifies at `retry_at_secs`.
  - Doc nit: `GiftsStage::First` (line 345) still says "or not sent yet", which `FirstAsking` now covers.
- **`src/premium_hub/ton.rs:409, 577` (`GramsPurpose::Revenue`, `GramsHub::revenue`), reducer at `src/state/domains/payments/grams.rs:37-41, 63`: `getGramRevenueStatistics` has no stage.** Its answer is taken by purpose with no `RequestId` check, and its error is `=> {}`. A late answer from an older open overwrites a newer one, and a failure hides the withdrawal section with no error. Fix: `revenue: Fetch<GramRevenue>`, settled by `RequestId`.
- **`src/paid_messages.rs:565-573` (`trust_loaded`): every read error becomes "no file".** `read_to_string(..).ok()` treats permissions and I/O errors like a missing file. The next `remember_trust` then overwrites the file with one entry, and the trusted prices are lost. Fix: only `ErrorKind::NotFound` means `None`. Other errors go to `TrustFile::LoadFailed { retry_at_ms }`, with no write until a read succeeds.
- **`src/ui/paid_reaction_ui.rs:124` (caller of `PaidReactions::begin_undo`): the toast's Undo drops the `Err` from `undo_paid_reaction`. Plausible.** The entry stays `Waiting`, and the Stars are committed at `commit_at_ms` with no message. Fix: on `Err`, show "Couldn't undo", or hold the entry and retry the undo on the `Stuck { settle: Undo }` backoff.
- **`src/ui/new_chat/mod.rs:300-316` (`settle_new_chat_stage`): a settled type Save leaves its `NewChatState::type_saves` rows for the session.** Only `Creating` is let go. Fix: when `left` is `Type { save: Saving(sent) }` and the new stage differs, call `live.driver.forget_new_chat_type_save(&sent)`.
