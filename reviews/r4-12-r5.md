## Failures

1. **src/ui/video_player/backend_ffmpeg.rs:680-718. Test hangs instead of failing, and the second ordering is untested.**
   - What is wrong:
     - `a_refused_reopen_still_fires_a_wake_the_old_player_settled_for` asserts with `heard.recv()`. Without the fix the wake sits in `backend.open_wake`, which keeps the `woken` sender alive, so `recv()` blocks forever. The test hangs and only a harness timeout ends it. That relies on a timeout, which AGENTS.md and the no-timeout rule forbid. The wake runs synchronously: the reopen closure waits for `first_open_done`, so the first player's open has settled before `Err` returns, and the re-registration's `on_open` calls the wake on the test thread inside `set_volume`.
     - The r4 review asked for both orders of the refused branch. Only "the first open settles during the refusal" is tested. The other one is missing: the refusal comes while the first player is still opening, then its open settles. That case is where two forwarders are queued on the same player and the "once" in the round 5 decision row matters.
   - Fix:
     1. In the existing test replace `assert!(heard.recv().is_ok(), "the wake fires")` with `assert!(heard.try_recv().is_ok(), "the wake fires inside set_volume")`, keep the `try_recv().is_err()` "once" check.
     2. Add `a_refused_reopen_while_the_old_player_opens_fires_the_wake_once`. Gated first player, register the wake with `backend.on_open`, set `reopen_with` to a closure that returns `Err("refused".into())` without touching the gate. Call `set_volume(0.5)`, assert `!backend.options.want_audio` and `heard.try_recv().is_err()` (not yet open). Register a probe with `backend.player.on_open` that sends on a second channel, release the first gate, block on the probe's `recv()` (it runs after both forwarders, and the sender lives in the queued probe until it runs, so this cannot hang on a correct build). Then assert `heard.try_recv().is_ok()` and `heard.try_recv().is_err()` (once).
   - Both tests then fail with an assertion, not a hang, if the re-registration or the "takes from the slot" step is removed.
