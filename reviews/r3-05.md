# Review of r3-05 (Opus, 2026-11-12). Verdict: merge after these fixes

Line numbers are on origin/claude/sweep-r3-05.

- 08-024: the per-message `MessageReactionBook` only forgets an entry through `QuillApp::close_message_menu` (src/ui/context_menu_keys.rs:423-437). Two common exits skip it. First, opening a menu in one window closes the other windows' menus with a bare `app.message_ui.menu.close_message()` (src/ui/reactions.rs:52-58). Second, a chat window closed with its menu open goes through `forget_chat_window` (src/ui/chat_window/mod.rs:678), which never closes that menu; the doc entry admits this case. Either way the closed menu's entry stays in the book. Under the old single slot it was replaced by the next ask; now it lingers until the 16-entry cap (src/state/media_library.rs:182-196) evicts it. While it stays: (a) `stale_messages()` (media_library.rs:237) re-sends `getMessageAvailableReactions` for every leftover Ready entry on each `updateActiveEmojiReactions` or `updateChatAvailableReactions` (src/connect/stickers.rs:842-848), for menus nobody shows, up to 16 requests at a time; (b) `ready_options()` keeps the custom emoji of every leftover entry in the wanted set (src/emoji/mod.rs:662). The cap hides an owner exit that is missing. Fix: in `close_message_menus_of_other_windows`, call `app.close_message_menu()` inside the `in_every_window` closure instead of `menu.close_message()`. In `forget_chat_window`, close the window's message menu the same way inside its `in_window_scope(Some(chat_id), ...)` (for example from `farewell_window`). With every exit forgetting its entry, drop `MAX_REACTION_ENTRIES` and the retain step in `begin`. Add a test: a menu open in window A, a menu opened in window B, then A's entry is gone and a stale mark re-asks only B's message.
