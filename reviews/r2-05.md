# Review of claude/sweep-r2-05: FIXED by the reviewer, merged into claude/sweep-r2-followup
## Confirmed defects (all fixed on the branch)
1. src/agent/pacing.rs + src/agent/tools/write/common.rs + src/agent/tools/td_call.rs (01-002, 01-010): `release` gave back the chat slot and the new-person slot but not the any-chat slot (`next_any`), so a send that never went out still delayed the next write to every chat. `take_write_turn` committed its turn before the TDLib call, so a failed non-send write kept its slots. The tests still went through the process-wide queue with real waits, and one returned early on `Err` without asserting anything. Fix: `Booking` remembers the any-chat slot it replaced and `release` restores it unless a later turn moved on; `take_write_turn` returns the `Turn` and `settle_turn` commits it only when the call worked (`change_steps` commits when any step went out); tests run on `State`/`book` with explicit instants.
2. src/calls/share_links.rs + src/connect/group_calls/admin.rs + state arms (01-034, 01-035, 01-036): `ShareLink::Fetching` still had no request id, answers and errors were matched by the speaker bool, and `plan()` marked a slot Fetching before the send. A late answer of an earlier click filled the next click's slot, and a failure of an old request raised the error for the new one. Fix: `Fetching(RequestId)`, set by `sent()` after the send worked; `answered(request, link)` and `failed(request)` act only on the slot that request owns; a refused send leaves the slot as it was.
3. src/connect/moderation/members.rs + src/state/domains/groups/state.rs (10-058, 10-059): a refused search with no earlier page stayed Loading; only the "had a page" case was restored. Fix: no page means `Failed` with the send-failed line, and the refused query is remembered so the picker's Retry asks for the same text. Test added (two refused searches in a row).
4. src/ui/group_type_box/mod.rs + src/state/domains/groups/group_type.rs (10-068): Save with a failed invite-link count refetched, showed a note and returned, so a count that keeps failing made the box impossible to save. tdesktop `EditPeerTypeBox` treats a failed count as zero (`.fail → done(0)`). Fix: a failed count reads as zero as in tdesktop; Save waits (button shows loading) only while the count is in flight.
5. src/ui/group_type_box/mod.rs (10-069): the debounce was still a detached task matched by a version from a process-wide static (`NEXT`, added to scripts/ui-statics.txt). Fix: `LinkCheck::Pausing(Task)` owns the pause; a keystroke replaces it and closing the box drops it; the static and its ui-statics line are gone.
6. src/ui/group_type_box/sections.rs (10-067): a box whose links were never fetched (`None`) was drawn as Loading forever. Only `Loading` draws the spinner now.
7. src/ui/story_viewer/{mod.rs,live_story.rs,live_state.rs} (13-043): a join whose send is refused left `Joining { request: None }`, which nothing ends, and Retry rebuilt the same stage through `forget_call_seen`. Fix: a refused send goes to `Refused` (Join button again); `forget_call_seen` is removed.
8. src/export/worker.rs (03-B003): after the fix a file that was already saved still failed its chat when TDLib did not answer the cache release, and a chat cut short by a TDLib error lost the HTML page of messages already written to the JSON. Fix: an unanswered release leaves the copy listed as a leftover and goes on; the partial chat flushes its last page before returning the error. Test added.
