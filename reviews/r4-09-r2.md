## Failures

### Items from r4-09 that are not fixed, or were fixed with a regression

- **scripts/check-owned-timers.py:117-127 (`rearm_hits`). The re-arm rule can be dodged.**
  - **What is wrong:** `DEADLINE.search(body)` runs over the whole function body. One `due`, `deadline` or `remaining`, or any `*_wait(` call anywhere in the function, exempts a fixed-period re-arm in another branch. The self-test (scripts/test_shape_guard.py:238) has no case for this.
  - **Three sites at the tip pass only through this hole:**
    - src/ui/notify_windows/mod.rs:796-807 with :895-904. `arm_notify_clock` re-arms every `INPUT_CHECK_MS` (300 ms) on `(None, true)`, and also while `windows.hovered.is_some()`. It is exempt only because its body says `due.saturating_duration_since`.
    - src/ui/media_viewer/actions.rs:621-629 (`viewer_idle_check`). The `held` branch re-arms every fixed `VIEWER_WAIT_HIDE_MS` (1.1 s). It is exempt because the other branch calls `controls_hide_wait_ms(`.
    - src/ui/os_menus/mod.rs:468-474 with src/ui/os_menus/sync.rs:84-91. `registry_wait()` is `REGISTRY_MAX_AGE` minus the age of a read, and every expiry forces a fresh read. So it is still a 10 s disk poll for the app's life, including while hidden or locked: the old constant under a computed name.
  - **Previous review asked:** allow lines with the real reasons for the notify clock and the menu sync (g-336 / 19-003, g-341). Neither was added, and the guard now passes them.
  - **Fix:**
    1. In `rearm_hits`, test only the timer's own argument with `fixed_timer`. When the argument is a plain identifier, resolve its `let` binding in the body and test that. Add self-test cases: a fixed timer in one branch beside a deadline in another, and a `let wait = if held { CONST } else { deadline }` binding. Both must be flagged.
    2. Notify clock: drop the `hovered` arm (:902). Every way a window goes already starts a fade, and that clears `hovered` through `notify_settle_hiding`. The `(None, true)` idle-input check has no OS event, so it needs an allow line `poll:QuillApp::arm_notify_clock` with that reason.
    3. Menu sync: watch the registry file, or add `poll:spawn_menu_sync` with the honest reason: other processes write the registry with no signal, so Quill reads it every 10 s.
    4. Viewer idle clock: arm no timer while held. The pointer leaving the controls and the end of a drag call `viewer_note_activity`, which re-arms with a real deadline.
  - **Owner decision:** both allow lines would go beyond the two that were restored. The owner must approve them, or the polls must go.

- **src/ui/inline_playback.rs:407-428 with src/ui/app_render/window_upkeep.rs:56 (g-382). S3 regression, confirmed.**
  - **What is wrong:** the record step now runs only from a window's frame, through `request_animation_tick`, which is gated by `TickGate::App`. `tick_wanted` (frame_clock.rs:794) refuses every frame request while Quill is behind another app. `recording_tick` is the only caller of `check_recording` and `sync_voice_action`.
  - **Trigger:**
    1. Start a locked voice recording, or a round video.
    2. Cmd-Tab to another app.
  - **Effect:**
    - The peer's "recording…" status lapses after about 5 s, although Quill is still recording.
    - A failed mic or camera gives no note.
    - A round video that reaches its 60 s limit is not sent until Quill comes back.
  - **Fix:** while a capture runs, request the step with a gate that passes in the background (`request_background_animation_tick(RECORD_FPS)`, the `TickGate::Sound` path). Or, while no window is active, hold one deadline task to `RecordTick::Next(due)` in the recording stage.

- **src/ui/peer_qr/gift_art.rs:294-297 (`qr_gift_tile_image`). S3 regression, confirmed.**
  - **What is wrong:** the new `tiles.retain(..)` drops the `Ready` tiles of the old size without `image_budget::retire_all`. A Quill-made `RenderImage` leaves the atlas only through the retire sweep, and `GiftArt::clear` (:70-79) and `art.rs` `trim` both retire theirs. The old code retired every tile when the box closed. Tiles dropped by a resize are now never retired.
  - **Trigger:** open a QR box, open the Gifts panel, and drag the window edge. Every size the layout passes through leaves a set of gradient tiles in the atlas until quit.
  - **Fix:** take the removed entries out (`extract_if`, or drain, then re-insert the keepers), collect their `Ready` images and `retire_all` them. Extend the new tile test in src/ui/peer_qr/tests.rs to check that the old images are retired.

- **src/ui/media_viewer/fullscreen.rs:106 (g-372, the same hole on a second path). S4, confirmed by tracing the transitions.**
  - **What is wrong:** `Cancelling { .. } if window_fullscreen => (Self::Off, true)` toggles the window out but goes straight to `Off`, not `Exiting`.
  - **Trigger:**
    1. Press F.
    2. Press Esc while the window is entering full screen.
    3. The window reports full screen, so it is toggled out and the state becomes `Off`.
    4. Press F during the exit animation: `Off.enter(true)` goes to `InFullscreenWindow` with no toggle.
  - **Effect:** the re-entry is lost.
  - **Fix:** `(Self::Exiting { until: now + CANCEL_WAIT }, true)`, as `GoingBack` does. Add this case to `entering_during_the_exit_animation_asks_again_once_windowed`.

- **src/ui/marketplace.rs:172 with :275-284 (18-001 rework). S4 regression, confirmed.**

- **src/ui/marketplace.rs:30-52 with src/ui/marketplace_box.rs:21-36, 79-85 (18-001, still partial). IS, confirmed, with an S4 plausible bug.**

- **src/ui/group_call_state.rs:203-215 (`StreamJoining { call, _timeout }`) with src/ui/group_calls.rs:96-104 and src/ui/group_call_stream_join.rs:20-28 (16-008, partial). IS, plausible.**
