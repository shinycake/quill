## Defects (confirmed)

1. `src/ui/chat_list_state.rs` `PinStage::release` (about line 200): `let Self::Dragging(mut drag) = std::mem::take(self) else { return None; };` has already replaced `self` with `Idle` (the enum default) when it takes the `else` path. The old `finish_pin_drag` returned early and left the stage alone when no row was held.
   - Failing scenario: one left-button release on a dragged pinned row fires `on_drop` on the row (`chat_row/mod.rs:877`), then `on_mouse_up` on the list (`chat_list/sidebar.rs:513`), and possibly `on_mouse_up_out`, each calling `finish_pin_drag`. The first call turns `Dragging` into `Sliding`. The second finds `Sliding`, takes it, sets `Idle` and returns `None`. The drop slide and the lift settle never animate.
   - The same takes place for any click on a row during a `Sliding`: the slide is cut and its `next_press` is lost. A `Pressed` stage is wiped on every release.
   - `pin_drag_tests.rs` only asserts `drag().is_none()`, so it does not catch this.
   - Fix: match on `&mut *self`. Only replace the stage when it is `Dragging`, for example `if !matches!(self, Self::Dragging(_)) { return None; }` before `mem::take`. Add a test that calls `finish_pin_drag` twice and asserts the stage is still `Sliding`.
