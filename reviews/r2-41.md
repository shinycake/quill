## What was checked
- 14-008, 14-017, 14-026, 14-027: `Awaited` carries the `RequestId`. `WebAnswer { request, result }` is pushed by `apply` from `pending.id`, which is the id the send returned. The drain loops over every answer, so two in one poll are both seen. A replaced launch's answer finds no wait. Removing the "clear on ask" lines is safe because answers are matched by request.
- 14-018: `AccessStage::Granting(request)` is compared with `answer.request`. The error arm pushes the rolled-back `false` under `p.id`.
- 14-015 and 14-016: the verdict is recorded where the answer is applied (success, a verification URL, or an error). `forget_outcome` runs on a new form and a new payment. The old rules map across: paid wins while open or closed; closed with a refusal reads failed; closed with verification or a payment still out reads pending; untouched reads cancelled. A refusal between two polls is now seen. A payment refused locally by the driver records nothing and reads "cancelled", as before. `dialog_open` is a reading of the dialog, not a stage, so keeping it is fine.
- 13-061 and 13-062: `TranslateStage { Box, Choosing { under }, SkipList }` owns `source`, `ask`, `expanded` and `note`. Pick and Cancel both go back through `back_to_box`. `new_translate_dialog` releases the old job first. The job answer is read from the box under the chooser.
- 13-060: the toast owns its timer, and replacing or clearing the toast drops it.
- 14-044, 14-045, 14-046, 14-080, 14-081, 14-083: the `EngineHealth::read` precedence (failed, then not open, then end, then stall) matches the old order of tests. `LiveSource::read` and `phase` give the same result as the old `LiveInput` for failed, ended, idle and opening. `Intent` lives in `Stage`. `pause`, `sleep`, a seek from Ended and `observe_live` set state and intent in one move.
- 14-053, 14-054, 14-055, 14-074: one pointer holds one slider, and `set_value` never emits `Change`, so a sync cannot overwrite a held `Drag`. `SpaceHold::settle` drops the timer on every move out of `Armed`. The PiP `SeekLine` and `VolumeLine` writes in `sync_lines` sit behind the existing drag guards.
- 14-028: `take_dragged` is read once by the button click. `finish_press` still reads `dragged()` without consuming it, so the order is safe.
- 14-050, 14-071, 14-041: `DecoderLoad` is `Idle`, `Loading { _task }` or `Settled`. `PoolState` keeps the old retry and size rules. `request_lead` is derived from the same values `on_grid` uses.
- No new `unwrap`, `expect` or `borrow_mut` in non-test code. Toast tests use the manual clock. The dropped baseline lines are really gone. `closing_confirmation` was already in `implicit-state-allow.txt` as a setting set by the app.
- Skips (`settings_button`, `in_attachment_menu`, `looping`, `Engine::{ready,running,at_end,keeps_up}` and the AVPlayer buffer flags) are independent readings or settings. Sound.

## Nits
- `observe`: with a loop seek still landing, a status that is both at the end and starved now stays `Playing`. The old code moved to `Buffering`. This is harmless and arguably better (no spinner flash on a loop), but it is a change.
- The poll answer lists (`found`, `attachment_menu_bot`, `emoji_access`) keep answers that no flow waits for until the next drain. The drain runs every poll, so they are bounded. `forget_web_app_launches` clears all but `emoji_access`.
- `decoder_load.rs`: the comment says the task is dropped "once it returns". It is dropped at the assignment, inside its own update. Safe because nothing awaits afterwards, but the comment should say so.
- A stale `outcomes` entry from an earlier payment of the same invoice would end a watch at once if a checkout for it were reused without a new `getPaymentForm`. I found no such path.
