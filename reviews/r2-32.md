## Defects

1. 14-064, `src/ui/twofa_state.rs:166-218`. The entry (the 2FA flow split over `TwoFaBox` in `OnScreen` and `Session.auth_state.twofa_flow`, reset by hand together) was not converted. The `TwoStepUi` setters were made private and the hand-reset moved into four `QuillApp` methods. `TwoFaBox::Open::{confirm, notice}`, `TwofaFlow::{notice, code_wait}` and the 2FA session flow are still two owners kept in step by convention, and `twofa_step_done` still does not touch the flow. The doc table treats this as fixed. Scenario: an account switch or a lock that closes the box through any other path (a `Farewell`, a window close) leaves `code_wait` set in the session, and the next open shows a half-finished step. Fix: put the recovery step's `code_wait` and `notice` inside the one stage value (`TwoFaBox::Open`), or make the session flow derive from it. Otherwise record it as skipped, with a reason that is not "private setters".
2. 14-056, `src/ui/video_editor_stage.rs:20-45`. The range is still stored twice. `EditorStage::Ready` and `Encoding` hold `edits: VideoEdits` (with `from_ms`, `till_ms`, `cover_ms`) beside `timeline`. `edits()` overwrites those three from the timeline, and the doc comment says the stored range "is not used". That is a side copy ignored by convention, which is the entry's shape. Any reader of the stage's `edits` directly gets stale values, and `become_ready` and `begin_encode` must keep copying both. Fix: split the range out of the stored value (a `ClipEdits` without from, till and cover), or store only the timeline's range.

## Reviewer's notes for the fix round
Both defects stand as written. For defect 1 (14-064) a skip is acceptable only with a reason proved from the writers: name every path that closes the box (account switch, lock, `Farewell`, window close) and show that each one also ends the session's flow; otherwise move `code_wait` and `notice` into `TwoFaBox::Open`.
- Before fixing anything, merge `origin/claude/sweep-r2-followup` into the branch (it is the integration branch of the bundles merged so far) and resolve overlaps in favour of its shapes; do not rebuild a value another bundle already rebuilt. Then run the four shape guards without `--prune` (`check-request-match.py`, `check-owned-timers.py`, `check-refcell-borrows.py`, `check-stage-enums.py`), fix what they report in code, and only then prune. A guard hit a fix introduced is fixed, not baselined; an allow line needs a reason that is true of the code (a ticket that is not a `RequestId`, an OS callback with no update to wait for).
