## Failures

- **src/ui/polls/option_media_tests.rs:93-121 (`a_new_add_clears_the_last_refusal`): the test passes without its fix.**
  - What is wrong: with no live client, the second Add goes down the demo branch of `submit_poll_add_option` (checklists.rs, after the `add_poll_option` match). That branch sets `self.message_ui.poll_add_option = None`. So `refused(app)` is None because the panel is gone, not because the refusal was cleared. Delete the `clear_refusal` call at checklists.rs:586-589 and the test still passes.
  - Fix: make the second Add end with the panel still open. For example, set `panel.attach.media` to `OptionMediaSlot::Preparing { .. }` before the second submit. That submit clears the refusal and then returns at the "wait for the video" check with the panel kept. Assert `app.message_ui.poll_add_option.is_some()` before asserting that `error()` is None.

- **third_party/gpui-component/src/root.rs:464-485 (`close_dialog_by_id`): closing a dialog that is not on top moves focus away from the dialog above it. S4, confirmed by reading.**
  - What is wrong: `close_dialog_at` returns the closed dialog's `previous_focused_handle`, and `close_dialog_by_id` focuses it. For the alert under another box, that handle is whatever had focus before the alert, below both. This is exactly the case the round-3 fix exists for.
  - Trigger:
    1. Quit while exporting. The Stop and quit alert opens.
    2. A shell box opens over it.
    3. The export ends, and `quit_gate_upkeep` closes the alert by id.
  - Effect:
    - Focus leaves the open box, so Escape, Enter and typing go to the window behind it.
    - The box above still stores the alert's focus handle as its `previous_focused_handle`. When it closes, focus goes to that dead handle, or nowhere.
  - Fix:
    - In `close_dialog_by_id`, when `ix` is not the newest non-closing dialog, do not focus the returned handle.
    - Instead, hand the closed dialog's `previous_focused_handle` to the first non-closing dialog above it, before the remove or exit.
    - Focus only when the closed dialog was the newest.
    - Extend `the_exports_ending_closes_the_alert_not_the_box_above` to assert that the box above still contains focus.

- **third_party/gpui-component/QUILL-CHANGES.md: the new kit patch is not recorded.**

The new `WindowState::last_dialog_id`, `close_dialog_by_id`, the `close_dialog_at` split, and the `WindowExt::{last_dialog_id, close_dialog_by_id}` methods have no entry.

- **src/ui/threads.rs:232-235: the paging half of "jump to root" ignores the goal's thread. IS, plausible.**

The thread upkeep still matches `ThreadRoot { .. }`, so it pages older replies of whatever thread is open. It also takes the goal on that thread's `OlderEnd::Failed`.   - Fix: match `Some(ScrollGoal::ThreadRoot { thread_id })` and compare it with the open thread's `thread_id`. On a mismatch, `take_goal()` and return.
