## Defects

1. `src/connect/core/mod.rs:623` (05-047): the write is retried on every ingest while `data_storage != data_storage_persisted`. Scenario: `data_storage.json` unwritable (read-only dir, full disk) after the presets seed or an auto-download save: `write_json_atomic` now runs on every TDLib update batch for the rest of the session; before, once. Fix: record the attempt (set `persisted` even on failure) and surface the error through `data_storage_save`, or retry only when `data_storage` changes again.

2. `src/state/domains/settings/state.rs:292`, `notify_accounts.rs:225`, `session_apply_messages.rs:479` (05-046): `attention_chats: Vec<ChatId>` is read only as `!is_empty()` after `take`. It is the same one-shot flag in a new type; the chat ids are never used, and the allow-line was removed rather than the shape. Fix: carry the attention request on the `QueuedNotification`/notifier drain that already exists, or delete the field.

3. `src/state/domains/payments/state.rs:197` (`Checkout.request`), `connect/payments.rs:61,102` (05-032): `request: Option<PaymentRequest>` still sits beside `form: CheckoutForm`; they are written independently (validate and submit set `request` directly). `Checkout::failed` relies on `request == None` to mean "no form". Request and form are still two fields kept in step by hand. Fix: put the invoice inside the `CheckoutForm` variants (Loading/Ready/Paid/Verifying).

4. `src/state/domains/stickers/manager.rs:21` (05-063): `CommitStage::Sent(id)` is never left on the step's answer, only on failure or the next send, and in-flight is still derived by scanning `requests.pending` (`manager_change_pending`). This is exactly the entry's complaint, relabelled. Fix: clear to `Queued` on the answer (ok and error) and drop the registry scan.

5. `src/connect/sticker_creator.rs:236`: `emoji_set_request(GetInstalledEmojiSets)?` no longer re-arms anything when its send fails (the old `creator_refetch_sets = true` retried both lists). Scenario: edit a set, installed-sticker refetch goes out (list leaves `Outdated`), emoji refetch send fails: emoji sets stay stale until some unrelated refresh. Fix: mark the emoji installed list `Outdated` on that error, as the sticker list does.

6. `src/state/domains/payments/earn.rs:562` + `ui/earn/withdraw.rs:144` (03-A007): the `Failed`/`Unavailable` ad-account stages are stored but the UI reads only `ready()`; a failed `getStarAdAccountUrl` is still invisible and has no Retry. Fix: draw the Failed line with Retry, or skip the entry citing tdesktop (the doc claims the stages exist).
