# Review of claude/sweep-r2-06: FIXED by the reviewer, merged into claude/sweep-r2-followup
Scope: the entries of bundles/r2-06.jsonl. The r2-06b entries belong to the b worker.
## Confirmed defects (all fixed on the branch)
1. src/ui/background_accounts/mod.rs + restart.rs (08-016): `has_work()` now counts failed clients and the poll calls `ensure_background_accounts` whenever a restart is due. When the pass cannot start the client (the app is locked, its old client is still closing, the folder waits to be deleted) the due time stayed zero, so the poll ran every 40 ms and each pass re-read the account list, the active account and the pending deletes from disk, for as long as the lock lasted. Fix: `Restarts::put_off` (first delay again, the failure count stays) for every client still due after the pass (`restart_due`); removed accounts forget their clock. Tests: the clock unit test and an app test with a client still closing.
2. src/ui/translate_ui/translate_bar_view.rs (14-042): "the chat was shown again" was read as "its scan is missing", but scans were dropped only inside a pass of another translated chat with a history, after the early returns. Closing the chat, or leaving it for a chat that is not translated, kept the scan, so a failed translation was in practice never asked again. The worker's test passed only because it cleared `translate.pump` by hand. Fix: scans of chats no window shows are dropped at the start of every pass; the test now leaves the chat and comes back.
3. src/location_picker/picker.rs (03-C010): a failed tile was dropped only on `move_ended` or a size change, so the view the user left alone stayed blank, which is the finding. The worker's test passed without the fix because its pan changed the tile key. Fix: `TileState::Failed(count)` and `Requested { extra, failed }`; a failed ask (or one that could not be sent, which used to be re-asked on every pass) is repeated up to three times, then waits for a move or resize. Tests rewritten to return to the very same view.
