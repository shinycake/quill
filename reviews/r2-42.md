## Defects

1. `src/video/mod.rs:402` (14-022, same function). The cancelled-between-spawn-and-publish branch still reads `if let Ok(mut guard) = slot.lock() && let Some(child) = guard.take()`. A poisoned lock skips the kill and the wait, so the child is left running and unreaped, which is the bug the entry named; only the other two lock sites were switched to `into_inner`. Fix: `let mut guard = slot.lock().unwrap_or_else(|p| p.into_inner());` there too.
2. `src/video_decode/mod.rs:475` and `:602`, `reattach.rs:14,32` (14-029). Only `detached` was folded into the queue value. `AudioTap::sounding: bool` and `AudioShared::starved: AtomicBool` are still the same fact kept in step by hand (`set_sounding` writes `starved = !sounding`; `reattach` seeds `starved: true` and `sounding: false` separately). Both are named in the entry's fields. Fix: drop `AudioTap::sounding` and read `!starved` (or make the output's state one value in the shared struct), so nothing mirrors it.
3. File-complete rule, files the bundle touched with findings left:
   - `src/video_decode/tests.rs`: `thread::sleep` at 28, 335, 346, 366, 441, 475, 512, 514, wall-clock deadline loops at 23, 435, 469, and `assert!(taken.elapsed() < IDLE_WAIT / 2)` at 352. AGENTS.md forbids sleeps and wall-clock waits in tests.
   - `src/webauthn/ceremony_tests.rs:38-44`: `next` polls with `Instant::now()` and `sleep(5ms)` under a 5 s deadline. The new `Ceremony::wait` was added for the hybrid tests only; this helper and `no_key_until_the_timeout` still wait on the clock. Fix: use `wait` here too and a manual clock for the timeout test.

## Nits

- `web_app/trust.rs`: a file that parses badly is `Unreadable` for good, so a corrupt trust file is never rewritten and consent never persists (before, the next save healed it). Consider moving a corrupt file aside, then treating it as empty.
- `trust.rs`: a `forget_account` made while `Unreadable` is memory only, and the next successful reload merges the disk copy of that account back in.
- `hybrid/flow.rs`: an overflowing timeout falls back to "deadline now" (fails at once), where `hid_macos` falls back to a year; unreachable with `u32` milliseconds.
