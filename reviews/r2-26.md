The `Asking` stage is also never left by its request ending. Fix: leave `Asking` only when `keyword_lookups.waits_for(request)` turns false (answered or gave up, for that request), and restore the guard line if it is kept.

The message menu is still a separate slot, and each opener still calls `close_message_menu()` by hand. The entry named the message menu, and the doc says "Fixed". Scenario: a future opener forgets the call, and two menus show. Fix: make the message menu a `ContextMenu` variant or one owner type, so opening any menu closes the others by construction.
