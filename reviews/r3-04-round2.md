- **Regression: hiding ads before the own full info is cached creates a fake one, so the account's real full info is never fetched for the rest of the session.** `hide_own_sponsored` (src/state/session_sponsored.rs:364-368) inserts `UserFullInfoData::default()` for the own user when none is cached. It runs on the `toggleHasSponsoredMessagesEnabled(false)` ok (`accept_sponsored_hidden`, :373-374) and on `ReportSponsoredResult::AdsHidden`. After that, `send_user_full_info` returns `Ok(None)` because `user_full_infos.contains_key(&me)` (src/connect/contacts.rs:102-113). `fetch_business_own_info` also skips (src/connect/business_settings.rs:30-31), and `business_own_info()` reports `Ready` (src/state/domains/settings/business.rs:94-95). The trigger is a Premium user who hides an ad before opening their own profile or Business settings. The own profile and every Business screen then show default values: empty bio, no hours/location/greeting/away/intro, "Do Not Hide Ads" off (src/ui/business/build.rs:70). Saving from those screens can then write the blanks back. Fix: never insert a placeholder. Drop the `else` branch, so only a cached own full info gets `sponsored_enabled = false`. When none is cached, have the driver ask `fetch_user_full_info(me)` after the toggle ok or the AdsHidden answer; its answer carries `has_sponsored_messages_enabled: false`. Until it lands, derive the wait instead of storing it: `sponsored_hidden()` also returns true when `my_is_premium()`, no own full info is cached, and `requests.has_purpose_for_user(GetUserFullInfo, me)`. Update `hiding_ads_keeps_a_report_in_flight` (src/state/tests/sweep_is05.rs), `a_premium_lapse_shows_ads_again` (src/state/tests/sweep_r3_04.rs) and tests/replay_sponsored_live.rs, which pass only because of the placeholder. Add a test that hides ads with no own full info cached, then checks that `getUserFullInfo(me)` is still sent and that `business_own_info()` is not `Ready` before its answer. Also fix the stale doc at session_sponsored.rs:371-372 ("for the rest of the session").

- **Minor: the PsaLabels tests share a process-wide request counter.** `static NEXT: AtomicU64` (src/promotion.rs:291) hands out ids across every test in the module, so a test's ids depend on which tests ran before it. No assertion depends on the values today, but this is the shared-global test shape the sweep removes. Fix: give `ask` a counter the test owns (for example `next: &mut u64`), or keep ids local to each `PsaLabels` (`RequestId(labels.asks.len() as u64 + 1)` per pack).
