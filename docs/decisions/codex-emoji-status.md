# Emoji status selection and recent history

The existing emoji settings dialog now offers recent, themed/trending, and default statuses, resolves custom emoji IDs through TDLib in batches of at most 200, and downloads available thumbnails through the shared file pipeline. Distinct custom emoji IDs remain cached across batches even when TDLib stickers have no standalone ID. Setting a status requires a confirmed Premium user; users can choose forever, 1h/2h/8h/2d, or positive whole custom hours within TDLib's int32 Unix date range, and remove the status with a null request. Clearing recent statuses shares the mutation gate. Lists and confirmation text change only after server success; refused requests preserve the list and expose a safe retry message. Old recent-list replies cannot restore cleared history. Refresh retries missing resolutions rather than spinning on empty or refused answers.

A runnable driver regression covers catalog resolution and batching, distinct identities, downloads without a selected chat, Premium and invalid-duration gates, request deduplication, Unix expiry, forever/null-clear, refusal text safety, confirmed mutation, and stale-answer rejection. All 1,362 core/replay/integration tests, strict core clippy, formatting, and local Mac UI compilation pass. Live Telegram changes and native interaction with populated status choices remain unverified. Upgraded-gift status selection and animated TGS rendering are outside these two custom-emoji status anchors; available thumbnails or Unicode fallbacks are displayed.
