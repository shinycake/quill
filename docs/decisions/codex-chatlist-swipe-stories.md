## Chat-list swipe actions and stories strip collapse (2026-10-08)

No README parity item exists for either feature, so there is no parity fragment.

### 1. Chat-row swipe actions ("Chat list quick action")

- **Gesture** (`ui/controls/swipe_handler.cpp`, `SetupSwipeHandler` wheel branch; core in `src/chat_swipe.rs`):
  - Only phased, precise two-finger scrolls (`Qt::ScrollBegin/Update/End`, here GPUI `ScrollDelta::Pixels` with `TouchPhase`). A gesture starts on `Started` only; a `Moved` with no started gesture (plain wheel, or macOS momentum tail, which GPUI maps to `Moved`) is ignored. Platforms that send no phases (Linux, Windows wheel) never start one, so they do nothing. Windows precision touchpads do send Started/Moved/Ended (`direct_manipulation.rs`) and work.
  - Deltas are scaled by `kSwipeSlow` 0.2 (`swipe_handler.cpp:23`) and accumulated; the first event with nonzero x fixes the direction and its own delta is dropped (`fillFinishByTop`, `state->delta = QPointF()`). Only fingers moving left (action direction `LeftToRight`, `dialogs_widget.cpp:872`) swipe a row; the other direction, or a row with no action, locks the gesture out like a vertical one.
  - Orientation lock: after the direction is known, `|dx| - |dy| > 1` (slowed units) locks horizontal, `< -1` locks vertical, in between stays undecided (`swipe_handler.cpp` `diffXtoY`, `kOrientationThreshold = 1`). Vertical stays vertical for the whole gesture. Horizontal consumes the wheel events (`cx.stop_propagation()`, tdesktop `scroll->disableScroll`), so the list does not scroll; vertical and undecided events reach the list untouched.
  - Ratio = accumulated slowed dx / `kThresholdWidth` 50 (`:77`). Translation: linear to ratio 1, then `16 * ln(1 + over/10)` damping (`DampedOverswipe`, `:36`); ratio capped at `kMaxRatio` 1.5 on release (`:78`). The row paints at **twice** the exact translation (`dialogs_layout.cpp:480`, `* -2`): 100 px at the threshold, about 136 px at the cap.
  - Reach: crossing ratio 1 starts a 0 to 1 bounce over `slideWrapDuration` 150 ms (`lib_ui basic.style:100`, `reachRatioDuration`); dropping below `kResetReachedOn` 0.95 re-arms it with a 1 to 0 animation (`provideReachOutRatio`).
  - Release (`processEnd`): the row springs back over `min(1, ratio) * 150 ms` (linear, `Ui::Animations::Simple`); if ratio >= 1 the action runs after `slideWrapDuration` (`base::call_delayed(st::slideWrapDuration)`, `dialogs_widget.cpp:891`), i.e. exactly when the spring finishes. Below 1 nothing runs. `TouchPhase::Cancelled` unwinds without running it.
- **Visuals** (`dialogs_layout.cpp:1015-1062`): the revealed panel is as wide as the shift, filled with the accent (`windowBgActive`), red for Delete (`attentionButtonFg`); the 20 px icon and a 13 px semibold white label (shrunk to fit 60 px, `SwipeActionFont`) are pinned to the right edge in a 60 px block (`dialogsQuickActionSize * 3`); at reach, a grey (`windowSubTextFgOver`) circle grows from the icon box centre (1.5 icons from the top and right) with radius `shift * reachRatio`. Quill uses `accent_strong()` / theme `danger` / theme `muted_foreground`. Deviation: tdesktop animates a Lottie icon from ratio 0.32; Quill shows the static lucide icon.
- **Actions** (`PerformQuickDialogAction`, `dialogs_quick_action.cpp`): Mute toggles forever-mute (Saved Messages disabled), Pin toggles, Read toggles read/unread, Archive toggles, Delete confirms. All reuse the chat-menu handlers (`apply_chat_mute`, `toggle_chat_pin`, `toggle_chat_marked_as_unread`, `toggle_archive`) so gating and live requests are unchanged; **Delete opens the existing `RemoveFromList` confirm dialog** and never deletes by itself, and is offered only where the menu's "Delete chat" is. The toast text is the status line (Pin keeps its own note: it may be the pin-limit message).
- **Setting**: `AppearancePrefs.swipe_action` (serde lowercase, default `Disabled`, as `core_settings.h:1222`; in tdesktop Disabled makes the swipe change folder, which Quill does not have). Settings > Appearance > Chat list rows > "Chat list quick action" radio list in tdesktop's order (`settings_chat.cpp`).
- **Quill glue** (`ui/chat_swipe_ui.rs`): a row with an action is wrapped in a div carrying the scroll listener (children register after the list, so it runs first and can stop propagation). Swiped rows render as `relative/overflow_hidden` with the panel under an absolutely shifted row; unswiped rows are untouched, so there is no per-frame cost for them. Frames come from `request_animation_tick(60)` called while the machine animates (reach bounce, spring back), attributed to the chat list slice; held swipes redraw from their own events via `notify_sidebar`. The action itself fires from a 20 ms timer that exists only while a swipe or spring is active (it also abandons a gesture silent for 600 ms, a lost-end safety net). Only the sidebar slice redraws.
- **Limitations**: the gesture direction follows the scroll delta sign, which GPUI does not report relative to the "natural scrolling" setting (`NSEvent.isDirectionInvertedFromDevice`); with natural scrolling off the swipe direction is mirrored. Middle-click quick action and tdesktop's Lottie icon are not part of this slice.

### 2. Stories strip collapse

- **tdesktop** (`dialogs_stories_list.cpp`, `dialogs_widget.cpp:1706-1860`): the strip is either collapsed (<= 3 overlapping 21 px avatars, `kSmallThumbsShown`, `dialogsStories.shift` 16 px, beside the search field) or expanded (77 px row, 42 px avatars, 10 px side skips, names at y 56, 11 px font), morphing by a layout ratio; expansion is driven by pulling the list down (virtual overscroll, `kExpandAfterRatio` 0.72 / `kCollapseAfterRatio` 0.68, `kFrictionRatio` 0.15) and it collapses once the list scrolls a row (`dialogsRowHeight`) past the pull.
- **Quill mapping** (`src/stories_strip.rs`, `ui/stories_strip_ui.rs`): the strip is the first row of the chat list's virtual list (height 77), with tdesktop's cell metrics and its `skipSide`/`skipBetween` spreading when the cells fit. The collapse ratio is `clamp(scroll_top / 77)`: a pure function of the list's scroll offset, no timer. Scrolling by the strip's height collapses it (the row scrolls away); returning to the top expands it. The compact stack fades in beside the search field with opacity `1 - expandRatio(1 - progress)`, using tdesktop's own `expandRatio` mapping (0 at `0.72 * 0.15`, 1 at 0.68) and its width follows the opacity, so the search field gives way smoothly. Tapping the stack scrolls to the top (tdesktop: tapping expands).
- **Deviations**: GPUI has no overscroll, so pulling the list past the top does not stretch the strip; the collapsed and expanded states cross-fade (avatars do not morph between the two layouts). The strip's sideways scroll is Quill-owned (offset state, `AxisLock`): sideways motion scrolls it, vertical motion falls through to the list, locked per gesture like tdesktop's `verticalScrollEvents`. The leading "New story" tile is Quill-only and stays first.
- **Perf**: strip tiles are cached by `Session::revision`; the stack and strip build only while visible.

Demo kinds `ready-swipe-mute`, `ready-swipe-reached`, `ready-stories-expanded`, `ready-stories-collapsing`, `ready-stories-collapsed` (light and dark). A new `QUILL_DEMO_CLICK` token `w:x,y,dx,dy,s|m|e` scripts phased trackpad events, so the real wheel path was run end to end: held swipe, release past the threshold (row sprang back, chat muted, toast shown), and a vertical-dominant gesture (no swipe). Unit tests: `chat_swipe` (direction lock, vertical lock-out, momentum ignored, threshold fire timing, spring, reach re-arm, cancel, stale gesture, curve, labels) and `stories_strip` (collapse mapping, expand ratio, stack geometry, cell layout, axis lock).
