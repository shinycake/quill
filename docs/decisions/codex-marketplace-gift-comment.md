# Marketplace gift comments

The Collectible gift dialog loads a named collectible with getUpgradedGift, shows its resale quote and recipient, and sends a personal comment through sendResoldGift only after an explicit price-labelled Buy action. It supports Stars and TON quotes, private-chat users and channel recipients, and receiver-only/public comment visibility. gift_text_length_max comes from TDLib; nonempty comments are refused until that limit is known and within the limit. Plain comments use formattedText with no entities.

The driver binds the loaded gift, recipient and confirmed price. It rejects stale prices, duplicate submissions, unavailable gifts and unsupported recipient types. An increased price returns to confirmation without another request; malformed prices discard the quote. Invalid/mismatched gift replies release loading and refuse purchase. Success is shown only for the correlated giftResaleResultOk response; its receipt ID may be empty for gifts sent to others. A changed gift-name input refuses Buy until that new gift is loaded. Account switching clears dialog inputs and client error state. Reopening an idle dialog clears the previous quote and drafts; logout closes it. Pending lookups and purchases retain their bound state until a response arrives.

Validation: the one driver regression exercises comment/privacy JSON, limits, duplicate refusal, no automatic purchase at an increased price, errors and unsolicited/confirmed success, including empty receipt IDs, Stars/TON and user/channel recipients, and malformed quotes/prices. Core tests, strict core clippy, formatting and native UI compilation passed. The reusable macOS accessibility smoke check in ready-marketplace-gift mode passed: real AX actions edit the comment, toggle visibility, refuse the stale gift name, then close and reopen a fresh dialog without the old quote or draft. Its owned-window screenshot was visually inspected. The fixture uses no live purchase; no Stars or TON were spent. Live-account gift purchase remains unverified.
