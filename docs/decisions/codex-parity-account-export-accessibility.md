# Account export and accessible controls

Settings → Data & Storage now offers folder-selected JSON account export, with optional media. A worker streams raw TDLib objects into private JSONL files, preserving sender identity, formatted entities, service messages and future fields. It exports profile information and photos, Telegram contacts, sessions, connected websites, account TTL, and every main/archive chat returned after loadChats reaches its documented 404 endpoint. History continues after short pages, skips the repeated anchor and stops when no older message remains. Sender users and sender chats are resolved separately. Media uses synchronous TDLib downloads, numeric filenames, and canonical paths restricted to the account file directory. Protected chats, non-saveable and self-destructing messages are excluded. Missing/expired media is recorded; cancellation or failure retains partial files with an incomplete manifest. Cancellation, disk writes and media copying do not block rendering; account shutdown drops the worker route, and a folder-picker result cannot start an export for a different account.

The synthetic regression exercises short and overlapping pages, archived chats, unknown fields, sender information, media copying, protected-content exclusion, private permissions, request correlation and cancellation. Native AX checks verify the destination and export controls without exporting the signed-in account. The full-account-export checkbox remains unchecked: TDLib 1.8.67 exposes getImportedContactCount but no getter for imported non-user contact records. The manifest records this limitation. This implementation exports the account information the pinned API makes available, rather than claiming complete Telegram Desktop takeout parity.

The UI control audit now covers text inputs, dialog titles, kit buttons, switches and checkboxes, custom clickable rows, media actions, privacy choices and picker cells. Inputs have explicit names, all dialog builders use the shared accessible heading, and custom click targets have roles/names and keyboard focus. A previous crash caused by adjacent kit Tables both using index zero is fixed in Data & Storage and Active Sessions; the tables are also named. Native AX fixtures verified sign-in phone/code/password, profile, sessions, storage, readable conversation/link roles, spoiler activation and composer editing. The settings smoke also activates the Wi-Fi download-settings row through AX and verifies Save appears. The reader-label checkbox can be completed independently of spoken VoiceOver verification.

VoiceOver remains unchecked. This Mac launched its first-use Quickstart rather than an active reader; the owned fixture and setup process were closed and the signed-in Quill instance remained running. The spoken-output script requires an already configured reader and does not enable it or change its settings. A phrase check on one profile fixture is only an initial spoken check, not proof across every flow.

Validation: 1,270 core unit tests passed (one pre-existing ignored), replay/integration tests passed, strict core Clippy and formatting passed, debug and release UI compiled, and the native settings/conversation checks passed. Unit-test media caches now use a process-specific test root so cache-sweep regressions cannot erase running-app or GUI-demo scratch files. This also removes the observed race between the old sweep test and native demos.
