# Chat row polish: draft prefix, send state, animations, title badges

Branch `codex/chat-row-polish-2` (the name `codex/chat-row-polish` was already used by merged PR #394).

## Tdesktop references

- `dialogs/ui/dialogs_layout.cpp`: `RowPainter::paint` decides `cloudDraft` (draft shown only when the entry has no unread item and the peer is not a forum); `PaintRow` draws the draft line with `lng_from_draft` ("Draft:") colored by `dialogsTextPaletteDraft` (`dialogsDraftFg`), a mini reply icon when the draft replies, and picks `sendStateIcon` (none beside a draft).
- `dialogs/dialogs_row.cpp`: `Row::CornerLayersManager` animates the online dot over `st::dialogsOnlineBadgeDuration` = 150 ms; `paintCornerBadgeFrame` scales the dot about its centre (`shrink = size/2 * (1 - p)`) with a ring stroke scaled by the same progress.
- `ui/unread_badge.cpp`: `PeerBadge::drawGetWidth` priority: SCAM/FAKE label, then verified (hidden behind an emoji status), then emoji status, then Premium star. Label style `dialogsScamFont` 9px semibold, 2px padding, 2px radius.
- Unread counters (`PaintUnreadBadge`, `dialogs_layout.cpp`): no animation in tdesktop.

## Choices

1. **Draft prefix.** `ChatSummary::draft_preview` mirrors tdesktop's rule: a draft shows only when there are no unread messages (count or marked unread) and the chat is not a forum; typing activity still wins. Behavior change: before, a draft hid unread incoming text. The row paints a red `Draft:` (theme `danger`) and a reply glyph for reply drafts; a reply-only draft shows `Draft:` alone. `sidebar_preview()` keeps its string form for search results. Not done: tdesktop shows `max(last message date, draft date)`; `ChatDraft` does not carry the draft date, so the stamp stays the last message date (and is absent for an empty chat with a draft).
2. **Outgoing status.** `ParsedMessage.send_state` (from `message.sending_state`) feeds `ChatLastMessage.send_state`; `ChatSummary::row_status()` returns None / Sending / Failed / Sent / Read, and None beside a draft. `updateMessageSendSucceeded/Failed` update the chat's last message directly, so the mark does not wait for the next `updateChatLastMessage`. A clock shows while sending. **Deviation from tdesktop:** tdesktop draws the same clock icon for failed sends; the brief asked for an error mark, so a failed send shows a red `!` disc (aria label "Failed to send").
3. **Animations.** Neither animates in tdesktop except the online dot, which matches at 150 ms. The unread badge has no tdesktop animation; a badge appearing (0 to N or dot) gets the same 150 ms ease-out scale (60% to 100%) and fade, so the list is consistent. N to M changes and disappearing do not animate. Implementation: `quill::row_fx::RowFxMap` (pure timing state, tested with injected `Instant`s) held on `QuillApp`; rows call `observe` while rendering, the first sight of a chat or an inactive window snaps, and `request_animation_tick(60)` is requested only while a toggle is mid-ease, so the clock stops once settled. No `with_animation`. Per-row cost is one hash lookup and no allocation after the first render of a chat. A row scrolled back into view after its state changed offscreen animates once (150 ms), accepted.
4. **Title badges.** Plumbed from TDLib: `user.verification_status` (with a fallback to the older top-level flags), `user.is_premium`, `user.emoji_status.type.custom_emoji_id`, and `supergroup.verification_status` via `updateSupergroup` (`Session::supergroup_verification`). `quill::peer_badge::title_badge` implements tdesktop's priority; `Session::chat_title_badge` resolves a chat. Verified uses the Lucide `badge-check` icon (added to Quill's scoped icon list), Premium a star glyph, and SCAM/FAKE a bordered red label. Emoji statuses are resolved with the same pipeline as preview custom emoji (ids added to `open_chat_custom_emoji_ids`) and drawn as the **still** image (no frame ticks, so many Premium rows keep the window idle); until the file lands the star shows. Supergroup/channel `emoji_status` does not exist in this TDLib schema, so only users carry a status. Saved Messages never shows a badge. Not done: the monoforum label, the "hide Premium badges" setting.
