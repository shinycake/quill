# codex/product-page — static product page on GitHub Pages

- `site/` is a static page with no build step and no third-party requests: system fonts, inline SVG icons, no analytics, no CDN. Screenshots are WebP copies of the README set (`docs/screenshots/readme-*.png`, demo fixtures only), about 640 KB in total.
- Sections: hero with an OS-aware download button, an experimental-software notice, features, a screenshot gallery, how it's built, "What's missing, and why", downloads with "What's new", questions, and a footer with the license and the no-affiliation notice.
- No performance or memory comparison with other clients. The owner asked to leave that out until optimization work is done.
- Every feature claim comes from the README highlights. The privacy claims were checked in code: the only non-Telegram request is the GitHub release check (`src/updater.rs`), which can be switched off ("Check GitHub Releases automatically on launch" in Settings). The local database key is in the Keychain, DPAPI, or a 0600 file. Screenshot blocking for secret chats exists on macOS and Windows (`src/ui/capture_block.rs`).
- "What's missing" (`site/data/missing.json`) was compiled from the README checklist's open and blocked items. Each TDLib and official-only claim was checked against `schema/td_api.tl` (1.8.67): communities only have create, rename and load calls; `sendResoldGift` has no signature field; `phoneNumberCodeTypeChange` and the in-store purchase calls are marked as official-app only. The picture-in-picture "blocked" claim was left out because it couldn't be confirmed against the current GPUI.
- Release data: `.github/workflows/pages.yml` runs `scripts/site-release-data.py`, which writes `site/data/release.json` from the latest published release. The release body is rendered by GitHub's Markdown API, which sanitizes it. The page matches the asset names the release pipeline uses (`quill-macos-aarch64.zip`, `quill-windows-x86_64.zip`, `quill-linux-x86_64-bundle.tar.gz`) and shows each asset's SHA-256 from GitHub's asset digest. With no release, it says so and links to the build guide.
- Rebuild triggers: pushes to `site/`, release published/edited/deleted, `repository_dispatch: site-refresh`, and manual dispatch.
- The platform detection returns nothing on phones and tablets (iPadOS and iOS report "Mac OS X"), so they get a plain "Download" button.
- Pages must be enabled for the repository with "GitHub Actions" as the source before the first deploy.
- Hero clip: a 22-second loop of the `ready-showcase` demo (invented chats, generated art, no live Telegram). It moves through a group, a private chat, a group with a poll and a photo channel, then opens, flips and closes the media viewer. `scripts/hero/record.sh` rebuilds it. The approach follows the professional recorders (Screen Studio, Cap, FocuSee): record with no cursor, then add a synthetic one in post.
  - The tour runs in-process. `QUILL_DEMO_CLICK` gained `p:ms` (pause), `m:x,y` (hover) and `k:key` steps. `QUILL_DEMO_CLICK_LOG` logs when each step ran. `QUILL_DEMO_WINDOW_ORIGIN` places the window. All of these are demo-capture only.
  - `scripts/hero/sckrec.swift` records only that window with ScreenCaptureKit: no cursor, no other windows, no shadow, 60 fps at the display's pixel scale. It prints the start time, so the step log lines up exactly.
  - `scripts/hero/composite.py` draws the cursor. It glides on eased arcs and arrives at each hover point when the app received that hover, so the hover highlight and the cursor match. It has 16-sample motion blur, a press dip on mouse-down, and a soft ripple. It also pastes back the window's traffic lights, which macOS replaces with a "being recorded" badge during capture.
  - The tour ends hovering the empty chat header, where it started. A 0.5 s crossfade covers the chat scrollbar still fading out, so the loop has no visible seam.
  - The page serves H.264: 2240 px (1.3 MB) on larger screens and 1280 px (0.6 MB) under 760 px, with a WebP poster (100 KB). The clip plays muted and only while on screen; with reduced motion it doesn't play and the poster shows.
