# Saved phone contacts through Telegram takeout

The pinned public TDLib API exposes an imported-contact count but no getter for the records. Telegram's documented contacts.getSaved method requires invokeWithTakeout. A narrow local TDLib extension, getQuillSavedContacts, starts a contacts-only takeout session, fetches those records under the takeout prefix, and finishes the session before returning. Success finishes with the success flag; a contact-query failure finishes without that flag and returns the original error. Separate one-shot ResultHandlers own each stage. No contact values or takeout identifiers are logged by the extension, and it never modifies contacts. A dropped export consumer does not interrupt the native cleanup chain; shutting down TDLib can still interrupt network cleanup.

The versioned patch applies to the pinned upstream source. The native build refuses unrelated tracked source changes and accepts exactly the already-applied patch for repeated builds. The official schema snapshot and checksum remain unchanged. The build is explicitly identified as a Quill extension. An unextended runtime, takeout delay, or other contact error is retained in private saved-contacts.json and adds a manifest limitation. Returning an error is never interpreted as an empty contact list. The full-export checkbox remains unchecked: left-channel histories and the full takeout message-range path are still missing.

Sources: https://core.telegram.org/method/contacts.getSaved and https://core.telegram.org/api/takeout .

Validation: the streaming export regression covers both returned raw contact fields and TAKEOUT_INIT_DELAY_3600, with different manifest limitations. The offline compiled-library check fails against the original runtime because the request is unknown and passes against the compiled extension, without creating a client or accessing an account/network. The patch was applied to pristine pinned files and reproduced all six modified source files exactly. All 1,274 core tests and replay/integration tests passed; strict core Clippy passed. This proves native registration and export-worker behavior; real server takeout acceptance remains unverified.
