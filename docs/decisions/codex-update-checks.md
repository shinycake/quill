# GitHub release checks

Quill checks the latest published stable GitHub release on launch, with a persisted opt-out in Settings → Appearance. The same panel has a manual Check for updates action, status and retry control, and release notes plus a repository-scoped release link. Available updates produce a dismissible banner leading to the notes. Version ordering uses the existing semver crate, avoiding lexical comparisons. No release (HTTP 404) remains a separate state and never claims up-to-date. Server failures, connection failures, malformed data, oversized responses, unstable versions, and invalid release links produce safe retry messages.

GPUI's desktop HTTP interface has no configured transport. The small blocking ureq client runs on the background executor, uses verified HTTPS only, no redirects, a 15-second total timeout and a 1 MiB response cap. It adds four lockfile packages; semver was already resolved. No Telegram identity or credentials enter release requests. The UI never installs automatically. Download/install/restart, post-update changelog, and unsupported-feature update cards remain unchecked.

Validation: the release regression covers numeric version ordering, equality/older versions, notes, absent release, HTTP and malformed errors, prereleases, invalid links, and the size cap. All 1,364 core/replay/integration tests, strict core clippy, formatting, and local native Mac UI compilation pass. Running `target/debug/quill --check-updates` against the real API returned "No published Quill release is available yet." with exit 0; the same command with a loopback unavailable HTTPS proxy returned a connection/retry message with exit 1. Populated update-banner and notes interactions are not live-release verified because the repository has no published release.
