# History GIF playback

History GIFs previously extracted only twelve frames and advanced every 400 ms. Playback now extracts the whole GIF or Telegram MP4 animation with the existing cancellable video decoder, on the background executor. Short clips use 24 fps; longer clips lower their sampling rate to retain the whole loop within 600 frames. Both image dimensions are bounded at 240 pixels. High frame rates on long clips require a streaming decoder later.

Frames are decoded before rendering, using the existing viewer helper. Native captures exposed asynchronous image-path loading repeatedly showing the same frame; in-memory RenderImage frames fix that shared rendering path. The helper also converts RGBA to the BGRA format used by GPUI. Playback uses elapsed time rather than incrementing once per delayed timer. Stop, chat changes and app teardown cancel extraction, terminate its owned ffmpeg child and delete private frame caches. Generation checks keep late worker/timer completions from replacing a newer player. Probe failures produce a retry message rather than pretending a static image is playback.

Validation: 1,363 core, replay and integration tests passed, with the external decoder regression excluded from the normal suite. Running that ignored regression explicitly passed for actual three-second GIF and MP4 files, verifies more than twelve frames, bounded portrait dimensions, distinct first/last frames, and cancellation before extraction. Strict core clippy, formatting and macOS UI compilation passed. `scripts/macos-gif-smoke.sh` passed against the native UI build: its demo uses the production player and owned-window captures verify visibly changing pixels inside the GIF. The demo requires no Telegram account. Live Telegram downloads and live-account interactions have not been verified.
