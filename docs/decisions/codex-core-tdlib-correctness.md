# Core TDLib-usage correctness pass

This was an audit of the core library (`--no-default-features`) for the TDLib flows a user hits all the time: chat list, history, read state and files. The references were the TDLib 1.8.67 schema doc comments (`schema/td_api.tl`) and Telegram X (TGX-Android/Telegram-X, read-only shallow clone, `app/src/main/java/org/thunderdog/challegram/telegram/`). Each fix has a regression test that failed before the change. No UI, dependency, README or DECISIONS changes. No new features: the archive paging fix loads a list the UI already shows.

## Fixed

1. **Chat-list membership updates moved rows.** `updateChatAddedToList` and `updateChatRemovedFromList` set or cleared `in_main_list`, `in_archive` and folder entries. These updates track `chat.chat_lists`, and the schema says it can disagree with positions (td_api.tl:3595, "A chat can have a non-zero position in a chat list even if it doesn't belong to the chat list..."). As a result, chats appeared with no order (order 0, or a stale order) and positioned chats were evicted. Rows now come only from `chatPosition`. TGX keeps `chat.chatLists` separate from `chat.positions` (`Tdlib.updateChatAddedToList` / `updateChatRemovedFromList`). Tests: `state::tests::chat_list::chat_list_membership_updates_do_not_move_chat_positions`, plus updated `folder_membership_add_remove` and `requests::chat_title_and_unread_updates`. In `replay_mute_and_archive_move_sidebar_lists`, the archive replay now includes TDLib's main-list `order 0` position.
2. **`updateNewChat` / `chat` positions were ignored.** `chat.positions` was never parsed. A chat that arrives already positioned (for example from `getChat`, or a new chat whose positions TDLib knows) stayed off the list until a later position update. Non-zero positions are now applied additively, like TGX `Tdlib.updateNewChat` → `TdlibChatList.onUpdateNewChat`. Test: `new_chat_positions_place_the_chat_in_its_lists`.
3. **The archive list was never loaded.** TDLib only sends positions for the loaded part of a list (`loadChats`, td_api.tl:11595), and only `chatListMain` and folders were ever loaded. The archive therefore showed only chats that happened to get an archive position. `loadChats(chatListArchive)` now pages once the main list returns 404, continues on `ok` and stops at 404. Its new purpose is `LoadArchiveChats`, so an archive `ok` never pages the main list. TGX loads every list it shows through `TdlibChatList.loadMore`. Tests: `connect::tests::chat_list::archive_list_is_loaded_after_the_main_list`, plus updated `driver_loads_chats_after_ready_then_send_text`.
4. **Mention and reaction badges went stale after reading.** `updateMessageMentionRead` and `updateMessageUnreadReactions` carry the chat's new `unread_mention_count` / `unread_reaction_count` (td_api.tl:10443/10450) and were unparsed. They now fold into the chat counters, as in TGX `Tdlib.updateMessageMentionRead` / `updateMessageUnreadReactions`. Test: `message_level_read_updates_refresh_chat_badge_counts`.
5. **History paging could loop forever.** The only end signal was an empty page. A page holding nothing older than its `from_message_id` (with offset 0, TDLib starts "from exactly the message from_message_id") repeats on every identical request, and the auto-load-older path re-sent it each time. `fetch_history` now stamps `from_message_id` on the pending request. The reducer ends paging when a page makes no progress, and short pages still page on (td_api.tl:11822). TGX ends on an empty page in `ListManager.processData`. Test: `connect::tests::messaging::history_paging_keeps_going_on_short_pages_and_stops_without_progress`.
6. **Chat export was truncated.** Export stopped at the first page shorter than 100. TDLib's first answer is often just the last message, so many exports contained one message. Paging now ends only when a page adds no message older than the oldest exported one, and duplicates are dropped by id. Test: `connect::tests::chat_state::chat_export_pages_history_until_a_page_adds_nothing`, a rewrite of the old short-page test.
7. **`from_cache` deletions punched holes in history.** `updateDeleteMessages` with `from_cache: true` only means TDLib unloaded its in-memory copy (td_api.tl:10699), but the rows were removed. A gap between surviving rows is never refilled because paging goes oldest-first. These updates are now ignored, like TGX `Tdlib.updateMessagesDeleted`. Test: `state::tests::requests::cache_eviction_does_not_punch_holes_in_loaded_history`.
8. **Deleted messages stayed in forum topic views.** `topic_histories` (the only thing the topic view reads) never saw deletions. Test: `state::tests::stories::deleted_messages_leave_loaded_topic_histories`.
9. **`openChat` had no paired `closeChat`.** `select_chat` opened every chat, but `close_open_chat` skipped chats whose type was not known yet. They now always pair, like TGX `Tdlib.openChat` / `closeChatImpl` (`openedChats`). Test: `connect::tests::chat_list::every_open_chat_is_closed_when_leaving_it`.
10. **Failed automatic downloads were retried on every ingest.** An avatar, thumb or sticker download that TDLib refused, or stopped without completing, was unstuck and then re-sent by the next ingest. Every update produced another `downloadFile` for the same dead file. Such downloads are now marked in `Session::stalled_auto_downloads` and skipped by the automatic `download_file` path. The mark clears when the user downloads the file, when the file completes, or when a notification-sound play request retries it, and on account close. Explicit cancels are not marked. TGX treats a stopped download as paused until asked again (`TdlibFilesManager.onFileUpdate` → `STATE_PAUSED`). Test: `connect::tests::messaging::failed_automatic_downloads_are_not_retried_on_every_ingest`.
11. **Hot-path clone (performance).** `rebuild_main_order` runs on every position, last-message and draft update, and it cloned every `ChatSummary` in both lists just to sort them. It now sorts `(order, chat_id)` keys. Ordering is unchanged and covered by the existing chat-list ordering tests.

## Deliberately left out

- **Jump-to-message gaps.** `GetHistoryAround` merges a disjoint slice into the single contiguous `HistoryState`, and `fetch_history` then pages from that slice's oldest row. Messages between the slice and the previously loaded block are never loaded. A real fix needs loaded-range tracking and newer-direction paging (TGX `MessagesLoader` replaces the list and pages both ways). That is feature-sized.
- **Other updates in topic views.** `updateMessageContent`, `updateMessageEdited`, `updateMessageInteractionInfo` and `updateMessageIsPinned` still update only the main history, so topic views can show stale content until refetched.
- **`viewMessages` scope.** `message_ids_to_view` views every loaded row of the open chat with `force_read: true`, not only the visible rows. This is a product decision tied to the UI's scroll position.
- **Remaining per-update scans.** `maybe_download_chat_list_photos` walks all chats on every ingest, and `apply_update_poll` walks every loaded history on each `updatePoll`. Both are linear and correct; bounding them needs indices.
- **Theoretical tombstone loop.** A history page made only of tombstoned older ids would still count as progress without moving the oldest row. TDLib does not return deleted messages, so this was not handled.
- **Exhaustion flags are never reset.** `chats_exhausted` and `archive_chats_exhausted` are never reset inside a `Session`. This only matters if one session object outlives a logout and re-login.

## Validation

`cargo fmt --all -- --check`, `cargo clippy --no-default-features --all-targets --locked -- -D warnings` and `cargo test --no-default-features --locked` all pass. None of this was exercised against a live account.
