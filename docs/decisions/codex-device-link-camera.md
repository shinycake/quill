# Camera-based device linking on macOS

Active Sessions now offers a bundled native camera scanner. AVFoundation supplies preview and frames; Vision decodes QR codes. The camera purpose is present in the app bundle and embedded in the standalone helper for developer runs. Permission denial and unavailable cameras remain visible in the scanner window. The helper returns a bounded candidate through a private pipe, exits after a match, and exits if its parent dies. Cancel, closing Sessions, changing account or losing authorization kills the helper and clears the zeroized candidate. No image is written to disk. The helper never has Telegram credentials.

Quill validates an exact tg://login?token= URI with a bounded nonempty base64url token. A separate accessible confirmation warns about cloud-chat access before confirmQrCodeAuthentication is sent. Duplicate requests are rejected; matching native session responses trigger an authoritative session-list refresh. A pending two-step password is shown as pending completion on the other device, rather than a completed login. Expired/rejected and malformed responses clear the pending state. Token buffers are zeroized, and tokens never enter diagnostics or accessibility labels. The native consent check caught and fixed both a misplaced poll hook and an inaccessible plain-text prompt.

Validation: strict native helper compilation and real CoreImage/Vision fixture decoding, without camera access; native AX confirmation/cancel/token-privacy proof using an injected Sessions fixture; URI, authorization, duplicate-submit, response-correlation, failure, malformed-session, 2FA-pending and diagnostics regression. All 1,276 core tests and replay/integration tests passed. This is macOS camera support; physical-camera capture and a real second-device login remain unverified. The checklist's opposite-direction QR wording needs reconciliation, and its box remains unchecked until the required behavior is verified.
