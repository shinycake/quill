# In-flight variants that wait for nothing Quill started (scripts/check-stage-enums.py).
# One per line: <rule>:<Enum>::<Variant> <reason>
unkeyed:Stage::Writing src/export/worker.rs: the export worker's own progress report (messages saved so far, of how many), which the progress box reads; nothing answers it. The export is ended by its owner (`ChatExport`: the worker link's cancel, and `SettleOnPanic` for a worker that dies), and every run ends in Finished, Failed or Cancelled
unkeyed:Stage::Decoding src/sticker_playback/player/engine.rs: the clip holds the index of the opener thread decoding it, which is what ends it: `WorkerEnd` (dropped when that thread returns, panics or never starts) fails every clip of its index (`State::opener_ended`). The index is a `usize`, which the check cannot tell from plain data
bare:GlyphSave::Pending src/launch_prewarm.rs: "not written yet", before any work starts; the first drawn chat list moves it on. Nothing is in flight in this stage
bare:GlyphSave::Saving src/launch_prewarm.rs: a process-wide stage of one detached writer thread per launch. The thread's `SaveEnd` drop guard ends it however the thread ends (return or panic), and a thread that could not start puts it back; there is no answer to match and nothing replaces it
bare:PhoneSuggestion::Asking src/chatlist_suggestions.rs: the "Is this still your number?" question is on screen; the user leaves it (Yes, No) or TDLib removes the suggested action. Quill started nothing
bare:StartupStep::Waiting src/tray_reveal.rs: what one look at the tray returned ("look again soon"), not a stored stage. The stored stage is `StartupWatch::Watching { since }`, which holds its deadline
unkeyed:BadgeStage::Pending src/icon_badge.rs: holds the unread count handed to the platform, and the platform answers with that count (`answered(count, ..)` acts only on `Pending(count)`); a worker that is gone ends it through `abandoned`. The count is a `u32`, which the check cannot tell from plain data
unkeyed:ReplacementProbe::Probing src/composer/edit.rs: holds the `ProbeJob` ticket of its ffprobe run, and only the answer of that job ends it; the edit ending drops it with the replacement. `ProbeJob` is a ticket type the check does not know
bare:GiveawayLaunch::Verifying waits on the person at the payment provider's verification page (3-D Secure), which sends Quill no answer; it was Verifying { chat_id } in the baseline and is now the value of that chat's entry in GiveawayLaunches. "Start over" on the form (end_verification) or the end of the session leaves it
bare:StreamStage::Running src/profile_photo_camera.rs: one atomic byte shared with the reader thread, so it cannot hold a handle. `CameraStream` owns the ffmpeg child the stage is about; the stream running out moves it to `Ended`, dropping the stream to `Stopping`
bare:StreamStage::Stopping src/profile_photo_camera.rs: the same atomic byte; written once by `CameraStream::drop`, which kills the child in the same call, and nothing waits on it afterwards
unkeyed:GiftsRest::Loading src/peer_qr/theme.rs: holds `GiftsAsk { serial, at }`, the box's own ticket for its gifts request; only the answer that carries that serial ends it, and `at` lets a lost request be given up on. The QR box is a pure reducer that never sees a RequestId
unkeyed:ThemeStage::Saving src/peer_qr/state.rs: holds the serial of its save (`SaveTicket { box_id, serial }` travels with the request), compared when the answer comes; a newer pick replaces it. The QR box is a pure reducer that never sees a RequestId
bare:CloseFriendsStage::Awaiting src/story_extras.rs: the editor is open before the list arrived and keeps no copy of the load. The fetch (with its request, its failure and the Retry) is the session's `CloseFriendsList`, which the panel reads while the editor awaits; the upkeep moves it to `Editing` when that list is loaded, and Cancel or the viewer closing leaves it
bare:DownloadStage::Running src/spell_download.rs: one atomic byte shared with the download worker thread, so it cannot hold a handle. It only moves forward: the worker ends it (`Done`, or `Cancelled` after a stop request), and the UI's stop request only moves `Running` to `Cancelling` in the `Progress` both sides share
bare:ChatSearchPhase::Searching src/state/chat_search_types.rs: the search of the bar's current generation. Every query bumps `ChatSearchState::generation`, the request carries it, and `matches_generation` drops the answer of any other.
unkeyed:BotStopStage::Running src/state/bot_stop.rs: the bot is still writing its reply, TDLib's own `updatePendingMessage` state with its `can_stop`; no request of ours (the Stop that is ours is `Stopping(RequestId)`).
bare:Launch::Starting src/telegram/hub.rs: TDLib is still opening its database and no client claimed the launch page; TDLib's own start, nothing Quill asked for. The first frame does not wait in this stage.
unkeyed:Launch::Asked src/telegram/hub.rs: holds the client whose first page the first frame waits for; that client's page or the wait's cap ends it. The stage is shared with the receive thread under a mutex and a condvar, so it cannot hold a Task.
bare:RunStage::Running src/telegram/hub.rs: the receive thread's own lifecycle, shared with that thread under a mutex. The hub holds the thread's JoinHandle beside it (`Hub::thread`) and joins it on stop.
bare:RunStage::Stopping src/telegram/hub.rs: a stop was asked of the receive thread; the loop's next check ends it and the hub joins the JoinHandle it holds beside the stage.
bare:BottomBar::Starting src/chat_bottom_bar.rs: the bar to draw, derived each frame from the chat; the stored stage is `StartState::Starting(RequestId)`, which holds the request.
unkeyed:CallEnd::Busy src/ui/calls_state.rs: the callee's line was busy (the call's discard reason). A summary the user leaves with Cancel or Redial; nothing is in flight.
unkeyed:CallWindowTarget::Busy src/ui/call_window_sync.rs: what the call window shows, read from the session each frame; "busy" is the busy line's summary, not work in flight.
unkeyed:SearchField::Opening src/ui/call_add_people.rs: the search input is built by the call window's first render of the box (it needs that window). No request or task; closing the box drops it.
