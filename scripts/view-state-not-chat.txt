# Fields of the per-view structs (the ones a chat window's `WindowSlot`
# swaps in) that name one chat's ids but are not the chat's UI state
# (docs/decisions/account-scoped-ui-state.md, section 9). Checked by
# scripts/check-screen-state.py: in `ComposerUi`, `MessageUi`, `HistoryUi`,
# `PickerUi`, `ShareUi` and `ViewerUi`, and in the src/ui structs they hold
# (`MessageUi.a11y`, `HistoryUi.pull`), a field whose type holds a
# `ChatId`, `MessageId`, `MessageKey`, `ChatMessage`, `DeleteConfirm`,
# `ComposerReplyTo`, `ComposerEdit` or a raw `i64` (TDLib's ids; outside a
# keyed map or set) is listed here with its reason, or it goes in `ChatUi`
# (ui/chat_ui_state.rs), which is replaced whole when the chat shown
# changes. A nested field is named by its path; `Option`, `Vec`, map
# values and enum payloads are walked too (round 7: a variant's payload is
# `Variant.0` or `Variant.field`). A name with `*` after it covers every
# field under it.
#
#   <Struct>.<field> [*] | <why it may outlive the chat it names>

ComposerUi.draft_load | carries its own chat and topic (the draft shown, the slot a restore asked for): a draft or restore for another slot never matches
ComposerUi.draft_load.Restoring.slot | the slot that asked for its draft to be restored next frame; the restore runs only if that slot is still the open one

ComposerUi.slow_mode_tick | the running 1 s tick task and its chat; it exits by itself when the chat changes and a newer chat's tick drops it, so resetting it would start a second task

ComposerUi.shown_draft | carries its own chat and topic: a draft for another slot never matches
ComposerUi.slow_mode_tick.Ticking.chat | names the chat of the running 1 s tick task, which owns it and exits by itself when the chat changes; the next gated frame replaces it
MessageUi.swipe_reply_start | one press gesture, carries its chat; the release checks it
HistoryUi.painted_ids | rebuilt by every paint of the history list
HistoryUi.seen | carries its chat; read once at the next render
HistoryUi.on_screen | rebuilt by every paint of the history list
HistoryUi.reported_visible | carries its chat: a repeat check, a new chat never matches
HistoryUi.sponsored.spots * | rebuilt from the open chat's placed ads after every history render (sync_sponsored_spots)
HistoryUi.ends | compared with the history synced next; a new chat's ends differ
HistoryUi.anchor.Anchoring.landed | compared with the session's highlight, which is the open chat's; the anchor starts a new chat with none
HistoryUi.anchor.Anchored.landed | compared with the session's highlight, which is the open chat's; the anchor starts a new chat with none

HistoryUi.live_location_tick | the running tick task and the chat it ticks for, as slow_mode_tick

HistoryUi.last_highlight | compared with the session's highlight, which is the open chat's
HistoryUi.live_location_tick_chat | marks a running tick task, as slow_mode_tick
ShareUi.forward.Bar.dest | the chat the forward bar waits in; kept across chats on purpose (dismiss_forward_for_view)
ShareUi.forward.Picking.bar | the forward bar the share box was opened over, which leaving the box returns to; it goes with the bar (dismiss_forward_for_view)
ViewerUi.clip.Playing.item | the media viewer's clip, which outlives a chat change (the viewer is the screen's)
ViewerUi.clip.Gif.item | the media viewer's GIF clip, as ViewerUi.clip.Playing.item
ViewerUi.pending_seek | a media-timestamp link's seek for the viewer's clip, as ViewerUi.clip.Playing.item

ComposerUi.suggest.stickers_dismissed | carries its chat and text: another chat never matches
MessageUi.a11y.focus.ArmedForFirst.0 | carries its chat; read against the chat viewed
MessageUi.rendered_sponsored | each ad carries the chat painted; the next frame reports only the open chat's
HistoryUi.anchor | the chat and topic the scroller last synced for: the check that resets it on a change
HistoryUi.row_hover.under | the row under the pointer, rebuilt by every paint and move
HistoryUi.row_hover.painted | the rows' hitboxes, rebuilt by every paint
HistoryUi.stream_reveal.Finishing.message | the bot reply finishing its reveal: the reveal names its chat and starts over in another
HistoryUi.pull.route * | where the pull gesture leads (next chat or topic) and the jump to it; `pull_sync` resets it when the chat or topic shown changes
HistoryUi.pull.window | the window and chat-window scope of that gesture, read by its jump, which `pull_sync` drops
ViewerUi.extra.share_at | the media viewer's "Share at" forward, as ViewerUi.clip.Playing.item
ViewerUi.extra.caption.key | carries its chat and message: the caption built for another never matches
