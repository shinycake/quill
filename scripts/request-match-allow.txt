# Purpose checks and unmatched answers that need no RequestId (scripts/check-request-match.py).
# One per line: <rule>:<Type::function> <reason>
unmatched:Session::apply_earn the own account's "has Stars statistics" fact (EarnState::self_stats, a Fetch<()>): any getStarRevenueStatistics answer for the own account proves it, the probe's or the open page's, so it is not tied to one request. The page's own data in the same arm is matched by waits_for
purpose:QuillApp::auth_submit_busy a double-submit guard, not an answer match: Enter in a sign-in field is refused while any sign-in submit is in the registry, the same test the driver makes before it sends one (connect/auth.rs). The answers are matched by the step's own request.
purpose:QuillApp::group_call_join_sent a drawn label, not an answer match: the video chat's mute button says "Connecting" while a join of that call is in the registry. The purpose names the call, the driver keeps one join per call (start_group_join) and matches its answer by the offer's request.
purpose:ConnectDriver::drop_in_flight cancels the request in flight for a purpose of a session-wide sticker or GIF list (one per session, never per chat or window): after a mutation changed the list, anything still out for it is older than the change and must not answer, so every request of that purpose goes, not one chosen by id
unmatched:MessagesState::pins_cleared a confirmed unpin-all (the `ok` of the request) is the new truth for the chat: the pinned list is empty whichever fetch was in flight, and a late answer of an older fetch finds `Ready` and is dropped because `Fetch::answered` takes only a waiting fetch
unmatched:GroupsState::welcome_pack_pushed `updateChatWelcomeMessages` is a push that carries the whole pack and answers no request: it replaces the pack whichever fetch was in flight, and a late answer of that fetch finds `Ready` and is dropped because `Fetch::answered` takes only a waiting fetch
