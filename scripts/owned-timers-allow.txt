# Timers that must run on a clock (scripts/check-owned-timers.py).
# One per line: <rule>:<Type::function> <what ends it, and why it has no event>
poll:run_poll_loop the shared poll loop itself (src/ui/wake_wait.rs): it rests on a quill::wake signal and ends when its pass returns None; the timer is only the gap that gives the thread back between two passes
poll:QuillApp::sync_omarchy_watch ends when Quill stops following Omarchy (`Omarchy::Watching` leaves to `Found`, dropping the task) or the app goes; no event because Omarchy signals a theme switch only by rewriting a file and Quill has no file-watch dependency; one stat every 2 s on a background thread, only while following
poll:QuillApp::spawn_event_log_poll the refresh of an open recent-actions page: TDLib sends no update for a new chat event, so getChatEventLog on a clock is the only way to see one; the page owns the task, which ends when the page closes and stops while no window is active (resume_event_log_poll restarts it on wake). Moved here from the baseline when the loop left start_event_log_poll
poll:QuillApp::spawn_viewer_session_tick the viewer's clip tick (src/ui/media_viewer/playback.rs): it drains `quill::media_session::take_commands` (an OS media-key queue with no wake signal) and the player's `take_error`; the clip stage holds the task, and it ends when the player is gone
poll:QuillApp::poll_viewer_headroom the display's EDR headroom while an HDR frame shows (src/ui/hdr_image/viewer.rs): the OS posts no event when the screen ramps in or out of extended range; the frame stage holds the task, and it ends when no frame or picture shows
poll:QuillApp::selection_drag_loop the held press's pointer: a pointer resting beyond the list's edge sends no event, yet must keep scrolling and extending the range; the task is the drag's stage (`SelectionDrag::Active`) and ends with the drag, the release or the window losing focus
poll:QuillApp::spawn_stress_redraw the performance fixture's 60 Hz redraw (`QUILL_DEMO_STRESS_REDRAW`, only in a screenshot-demo session with a stress size): the point is steady frames for a profiler, so it is a clock by design; it ends when the app entity is gone (its update errs). Real sessions never start it
detached:QuillApp::spawn_stress_redraw the same fixture redraw loop: a demo-only profiler aid with no stage to own it, ended by the app going away
poll:watch_disk_space the disk poll (src/ui/disk_state.rs): free space has no change event, so the data folder is read on a clock whose gap follows how fast the disk is falling (`next_read_in`); the task is held in `DiskUi::_watcher` and ends with it, and it must keep running while the window is hidden or locked because a full disk has to close the clients then too
