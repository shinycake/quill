# What the passcode lock does with each start that does not test a lock
# gate itself: an OS window, a helper process, a capture, an app-wide key
# hook or action handler, an account switch that skips the lock. Checked by
# scripts/lock_surfaces.py (run by scripts/check-screen-state.py), which
# says exactly what it proves.
#
# <path::fn> | <closer> | <reason>
# closer: a method `close_for_lock` (src/ui/passcode/lock_gate.rs) calls;
# `via:fn` when the start runs only through `fn`, which tests a gate;
# `-` when the lock need not reach it (say why); `refuses` for a function
# that must keep testing a gate itself.

# Closed by the lock.
src/ui/video_player/controls/pip/open.rs::open_pip_window | close_every_video_pip | a video PiP plays the account's media; it opens only from a viewer, which the lock closes too
src/ui/notify_windows/mod.rs::open_popup | close_all_notify_windows | Quill's notification windows show senders and text; one shown while locked hides the sender (`hide_sender`)
src/ui/device_qr.rs::start | clear_device_qr | the device-linking camera scanner is a helper window with the camera on, opened from Settings > Devices
src/profile_photo_camera.rs::start | close_cameras_for_lock | the profile or group photo camera; `start_camera` refuses a new start while locked
src/media_tools.rs::spawn_capture | via:start_video_capture | the round video recorder; the lock cancels a running one (`cancel_recording`)

# Refused while locked (they test a gate in a condition).
src/ui/deep_links.rs::pump_deep_link | refuses | a launch or OS link waits for the unlock, as tdesktop's start links (`checkStartUrls`)
src/ui/deep_links.rs::run_resolved_deep_link | refuses | the chat or box a link resolved to opens after the unlock
src/ui/web_app_ui/spawn_mini_app_window.rs::spawn_mini_app_window | refuses | a mini app whose URL lands while locked would show, usable, over the lock; TDLib closes the launch
src/ui/accounts.rs::switch_account | refuses | nothing behind the lock changes account; tdesktop empties the tray and Dock account items while locked
src/ui/os_open.rs::open_link | refuses | nothing opens in the browser or mail client while locked
src/ui/os_open.rs::open_web_link | refuses | as open_link
src/ui/os_open.rs::open_file | refuses | a file opened by a late answer would show over the lock
src/ui/os_open.rs::open_file_then | refuses | as open_file; the caller hears it did not open
src/ui/os_open.rs::reveal_in_folder_or | refuses | as open_file
src/ui/os_open.rs::reveal_from | refuses | as open_file
src/ui/passcode/lock_gate.rs::intercept_keys_unlocked | refuses | the app's key interceptors all go through it: no shortcut, capture or viewer key acts on a key typed on the lock screen
