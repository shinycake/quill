## Full findings

## growth-2: TDLib's file cache has no limit until the user moves a slider
- Severity: P2 measurable waste
- Kind: disk
- Platforms: macOS, Windows, Linux
- Where: `src/connect/settings/storage.rs:179` `set_storage_limits` has one UI caller, `apply_storage_sliders` at `src/ui/dialogs/local_storage.rs:405`, on slider release. `build_set_tdlib_parameters` (`src/connect/connect_flow.rs:62`) sets no limits and nothing sends `use_storage_optimizer` at startup. `src/storage_limits.rs:1-6` notes the optimizer only runs while that option is on.
- Trigger: any account that never opened Settings, Data and Storage. Every photo, sticker, autoplayed clip and voice note stays in `tdlib_files` for good.
- Effect and size: guess of 0.5 to 2 GB/day on a heavy account with default auto-download, and the disk use never falls by itself. Not measured: nobody has run `du` on a heavy account's `tdlib_files` for this audit.
- Why it is real: the Local Storage box reports "no limit" (`StorageLimits::size_limit` returns `None` while the optimizer is off). No decision doc chose that default. `codex-data-storage.md` only records that the sliders exist.
- What tdesktop does: `storage_account.cpp:184-187` starts from `Database::Settings()` limits. From memory those are about 1 GB each for the cache and the big-file cache and about a month. `lib_storage` is empty in the reference clone, so confirm the numbers before quoting them.
- Fix sketch: seed a default once per account. On the first Ready with no stored choice, send `options_for(Some(size), Some(keep))`, for background accounts too. Record a per-account `storage_limits_seeded` flag beside `DataStoragePrefs` (`src/data_settings.rs:229`). An explicit "no limit" later must stick. The owner picks the numbers.
- Proof plan: connect test next to `account_hygiene.rs:370`: the first Ready sends the four options once, a second start sends nothing, and a user's "no limit" is not overwritten.
- Scope: `src/connect` (auth Ready path), `data_settings.rs`, tests. Risk: an existing user's first GC frees a lot at once, and files they downloaded by hand can go. Check how TDLib's GC treats files in the Downloads list before shipping, and put it in the release notes.
