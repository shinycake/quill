## robustness-9: If a Quill instance hangs, launching it again does nothing and says nothing
- Severity: P3
- Kind: robustness
- Platforms: macOS, Windows, Linux
- Where: `src/main.rs:355-358`: on `Err(TimedOut)` from the owner, it prints to stderr and treats the launch as `Instance::Forwarded`, so the process exits.
- Trigger: the running instance is stuck (robustness-1 is one way to get there) and the user double-clicks the app icon.
- Effect and size: traced from source. After the 3 s ack timeout, the second process exits silently. The stuck window stays stuck, with no hint to force-quit.
- Why it is real: `eprintln!` reaches nobody in a bundled app.
- Fix sketch: on `TimedOut`, show the existing native startup dialog (`src/ui/startup_failure.rs`) saying the running copy is not responding and how to close it.
- Proof plan: a unit test on the decision: `TimedOut` maps to a new `Instance::OwnerStuck`, not `Forwarded`.
- Scope: `src/main.rs`, `src/ui/startup_failure.rs`. Low risk.
